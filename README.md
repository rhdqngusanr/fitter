# Fitter

**"이렇게 해주세요" 사진을 올리는 고객과, 자기 시공 포트폴리오를 올리는 반셀프 인테리어 작업자를 사진 기준으로 직접 연결하는 매칭 플랫폼.**

기존 인테리어는 종합업체가 전 공정을 받아 각 공종 기술자에게 하청을 주는 턴키 구조다. 고객이 내는 중간 마진과 시공자가 못 받는 단가는 같은 돈이다. Fitter는 그 중간을 걷어내고 고객이 공종 단위로 개인 시공자에게 직접 맡기는 구조를 만든다.

**왜 사진인가.** 일반 고객은 인테리어를 말로 설명하지 못한다. "밝고 화이트톤에 우드 포인트"는 열 사람이 열 가지로 해석하지만 사진 한 장은 정확하다. 그래서 여기서는 **고객이 올린 사진이 곧 요구사항 명세**다.

> 🚧 현재 상태: 스캐폴딩 완료, 기능 구현 전.
> 화면 시안 21종은 [여기](https://rhdqngusanr.github.io/fitter/)에서 볼 수 있다.

## 기술적으로 공들이는 두 지점

포트폴리오로서 이 프로젝트가 증명하려는 것은 기능의 개수가 아니라 아래 둘이다.

**1. 이미지 파이프라인.** 사진이 제품의 전부인 서비스다. 서명 URL로 스토리지에 직접 업로드해 파일이 서버를 경유하지 않고, 클라이언트에서 리사이즈·압축한 뒤 올린다. 서버는 확장자를 믿지 않고 매직 넘버로 실제 타입을 검증한다. 원본은 보관하되 목록 400px·상세 1200px 썸네일을 파생해 **목록에서 원본을 절대 로드하지 않는다.** EXIF 위치정보는 제거한다 — 고객의 집 좌표가 사진에 박혀 있기 때문이다. 업로드는 됐지만 등록되지 않은 고아 파일은 TTL로 정리한다.

**2. 컨택 상태머신.** `REQUESTED → ACCEPTED / DECLINED / CANCELLED / EXPIRED`. 핵심은 상태가 아니라 **주체**다. 수락은 수신자만, 취소는 요청자만, 만료는 시스템만 일으킬 수 있다. 전이는 도메인 레이어의 순수 함수라 DB 없이 테스트된다. 그리고 **연락처는 `ACCEPTED` 이후에만 응답에 실린다** — 마스킹된 값이 들어가는 게 아니라 키 자체가 없어야 하고, 이 통제는 컨트롤러가 아니라 응답 직렬화 레이어 한 곳에서 강제한다.

## 구조

```
apps/
  api/            NestJS. 도메인을 감싸는 바깥 링
    src/modules/  기능 모듈
    src/infra/    어댑터 구현 (prisma · storage · queue · events)
    src/common/   guards(역할) · interceptors(연락처 차단) · errors · logging
  web/            Next.js App Router
    (public)/     비로그인 공개 · SSR 색인
    (app)/        로그인 전용 · noindex
packages/
  domain/         ★ 순수 TypeScript. 프레임워크를 모른다
    pricing/      EstimatePolicy — 2차 견적이 들어올 자리
    ports/        storage · notification · event-bus · search
  shared/         web·api 공용 타입과 상수 (공종 코드, enum, 정책 상수)
```

**`packages/domain`에 프레임워크 import가 들어오면 빌드가 깨진다.** 패키지 경계가 물리적으로 막고, ESLint 규칙이 왜 막혔는지를 알려준다. 이렇게 해두면 스택을 바꿔도 도메인은 살아남는다.

같은 이유로 스토리지·알림·검색·견적은 전부 포트 인터페이스 뒤에 있다. 목록 API는 예외 없이 커서 페이지네이션이다 — 오프셋은 데이터가 늘면 반드시 느려지고 무한 스크롤에서 중복과 누락을 만들며, 나중에 바꾸면 API 계약이 깨진다.

## 스택

| 영역     | 선택                    | 이유                                                                  |
| -------- | ----------------------- | --------------------------------------------------------------------- |
| 언어     | TypeScript (strict)     | 프론트·백 단일 언어. 1인 개발 생산성                                  |
| 프론트   | Next.js App Router      | 공개 화면 SSR 색인 / 로그인 화면 noindex                              |
| 백엔드   | NestJS                  | Guard=역할권한, Interceptor=연락처 차단, DI=어댑터로 구조 원칙과 대응 |
| DB       | PostgreSQL              | 공종 FK, JSONB 견적 스냅샷, 커서 페이지네이션                         |
| 스토리지 | Cloudflare R2 (S3 호환) | egress 무료 — 이미지 서비스의 비용 급소                               |
| 큐       | BullMQ + Redis          | 썸네일 파생, 고아 파일 정리                                           |

Postgres + S3 호환 + Docker 조합이라 벤더 락인이 낮다. 선택 근거와 되돌리는 경로는 ADR-001에 전문으로 남겼다.

## 실행

Node 22 이상이 필요하다. 패키지 매니저는 pnpm이며 corepack으로 붙는다.

```bash
corepack enable pnpm
pnpm install
cp .env.example .env
pnpm build        # 워크스페이스 패키지를 먼저 빌드한다
pnpm dev          # api :3001 · web :3000
```

| 명령             | 하는 일                         |
| ---------------- | ------------------------------- |
| `pnpm dev`       | api와 web을 동시에 띄운다       |
| `pnpm build`     | 의존 순서대로 전부 빌드         |
| `pnpm test`      | 단위(도메인) + 통합(API e2e)    |
| `pnpm lint`      | ESLint. 도메인 순수성 규칙 포함 |
| `pnpm typecheck` | 타입만 검사                     |
| `pnpm format`    | Prettier                        |

커밋하면 husky가 lint-staged를 돌려 스테이징된 파일만 검사한다.

## 설계 문서

판단의 근거는 전부 옵시디언 볼트(`brain/`)에 있고 저장소에는 올리지 않는다. 사업 전략과 경쟁 분석이 함께 들어 있기 때문이다. 볼트에는 서비스 정의, 도메인 용어집, 확장 규약, 엔티티·상태머신 정의, PRD, 유저 스토리 39개, ADR, 그리고 화면 시안 검수 결과가 들어 있다.

코드에 달린 주석 대부분은 그 볼트의 어느 노트가 그 결정을 규정하는지 가리킨다. AI 도구로 작업할 때는 루트 `CLAUDE.md`가 진입점이고, 거기서 `brain/00-허브/세션 부팅 프로토콜.md`로 이어진다.
