### C-06 을 비로그인 공개로 바꿨다 (2026-07-26)

## 잠정 목록에서 바뀐 것

**컷 (3)**
- **C-08 스크랩 목록** — 콘텐츠가 0건인 초기에 스크랩할 게 없다. 2차.
- **P-06 승인 대기 안내** — 화면 하나를 쓸 일이 아니다. P-01 상단 배너 + P-03 빈 상태 카피로 흡수.
- **G-05 마이페이지** — 역할별 홈(C-02 / P-03)이 이미 마이페이지다. 설정만 남겨 G-05로 재정의.

**통합 (2)**
- G-02 로그인 + G-03 회원가입 → **G-02 하나**. 소셜 우선이면 두 화면이 사실상 같다.
- 기존 C-04 시공자 목록 / C-06 포트폴리오 갤러리의 역할을 분리했다. **갤러리(C-04)는 사진 탐색 = 비로그인 공개 SEO 관문**, **시공자 목록(C-06)은 조건 필터 = 로그인 후 후보 만들기**. 둘 다 필요하되 목적이 다르다.

**신규 (2)**
- **G-05 설정 · 계정** — 약관·탈퇴·알림 수신 동의는 법적으로 빠질 수 없다.
- **신고 접수** — 화면이 아니라 C-05 / C-07 / M-02 안의 모달. A-02가 받을 입력이 필요하다.

## 답해야 할 것

### 1. 역할 — 계정당 하나에 **동의**한다 (조건부)

근거 셋. ① 권한 모델이 단순해진다. 두 역할을 가지면 모든 목록·상세에서 "지금 어느 모자를 쓰고 있나"를 매 화면 판단해야 하고, 컨택 한 건에 같은 계정이 양쪽 당사자로 들어올 수 있다. MVP에서 감당할 복잡도가 아니다. ② PRO는 **승인 심사 대상**이다. 심사 단위가 계정이어야 승인·반려·정지가 깔끔하다. ③ 실사용 빈도가 낮다. 시공자가 자기 집을 고치는 경우는 있지만 서비스 초기 트래픽에서 무시할 수 있다.

다만 **스키마는 열어 둔다.** `User.role` 단일 컬럼으로 못 박지 말고 `User 1—N UserProfile(type: CUSTOMER|PRO)` 구조로 두되, MVP에서는 프로필을 1개만 만들 수 있게 애플리케이션 레벨에서 막는다. [[확장 규약]] 취지에 맞고, 2차에 "역할 추가"를 마이그레이션 없이 열 수 있다. 지금 필요한 탈출구는 G-05의 **역할 전환 요청**(관리자 수동 처리) 하나면 충분하다.

### 2. 비로그인 공개 범위 — **포트폴리오는 열고, 의뢰는 닫는다**

트레이드오프의 답이 비대칭인 이유는 사진의 **권리 출처가 다르기 때문**이다.

- **포트폴리오 사진 = 시공자 본인이 찍은 자기 작업물.** 업로드 시 "본인 시공·본인 촬영" 확인을 받으면 공개·색인 권리를 확보할 수 있다. 여기가 SEO 유입의 유일한 자산이므로 반드시 연다. → C-04, C-05, C-07 공개.
- **의뢰 사진 = 고객이 인터넷에서 긁어온 남의 사진일 확률이 높다.** [[리스크 - 레퍼런스 사진 저작권]]의 본질은 "공개 게시 + 검색 색인"이다. 로그인 벽 뒤에서 시공자에게만 보이는 건 리스크가 훨씬 낮다. → C-01, C-02, C-03, P-04, P-05 전부 로그인 필수 + `noindex`.

**공개 화면에서도 마스킹하는 것:** 시공자 연락처·실명·정확한 주소는 로그인 여부와 무관하게 M-02 수락 전까지 절대 노출하지 않는다. C-07은 비로그인에게 프로필과 포트폴리오까지만 보여주고, 컨택 버튼을 누르면 G-02로 보낸다.

### 3. 컨택 상태 변화가 일어나는 화면

한 곳으로 모은다 — **M-02 컨택 상세**. 상태를 바꾸는 버튼은 M-02에만 존재한다.

| 전이 | 발생 화면 | 비고 |
|---|---|---|
| (없음) → REQUESTED | C-07 하단 컨택 버튼 / P-05 제안 버튼 → 요청 시트 제출 | 생성만. 시트는 화면으로 세지 않음 |
| REQUESTED → ACCEPTED | **M-02** (받은 쪽) | 수락 즉시 같은 화면 안에서 연락처 블록이 인라인으로 열린다. 별도 화면 없음 |
| REQUESTED → REJECTED | **M-02** (받은 쪽) | 사유 선택(선택 입력) |
| REQUESTED → EXPIRED | 시스템 배치 (7일 무응답) | M-01/M-02는 결과만 표시 |
| ACCEPTED → 연락처 열람 | **M-02** | 열람 시점을 기록해 [[리스크 - 플랫폼 이탈]] 지표로 쓴다 |

M-01은 **상태를 보여줄 뿐 바꾸지 않는다.** 목록에서 스와이프 수락 같은 걸 넣으면 오조작이 나고, "연락처가 공개되는 순간"이 어디였는지 사용자가 기억하지 못한다. 되돌릴 수 없는 전이는 상세 화면에서 한 번 더 확인받는다.
