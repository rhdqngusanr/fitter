# 시안 대조 결과

> 구현한 화면이 `design/`의 시안과 얼마나 맞는지 항목별로 적는다.
> **[[시안 검수 결과]]와 다른 노트다.** 저건 시안 자체의 결함을 적은 것이고,
> 이건 시안과 구현의 차이를 적는다.

## 왜 이 노트가 생겼나

Phase 4 화면을 만들면서 **시안을 열지 않았다.** 디자인 시스템에서 컬러 토큰만 grep으로
뽑아 쓰고, 각 화면의 레이아웃·컴포넌트·상태는 즉흥으로 만들었다.

원인은 [[세션 부팅 프로토콜]]에 있었다. "디자인·화면 작업이면 [[화면 목록]], [[디자인 원칙]]을
읽어라"고만 되어 있고 **`design/`의 시안 파일을 열라는 지시가 없었다.** 노트는 "왜"를 담고
시안은 "무엇을"을 담는데, 노트만 읽으면 색만 맞고 구조는 새로 지어진다.

프로토콜을 고쳤고 이 노트로 차이를 추적한다.

## 토큰 — 고침 (2026-07-26)

`apps/web/src/styles/tokens.css`가 시안 정본과 어긋나 있었다.

| 항목 | 시안 | 구현했던 것 | 조치 |
| --- | --- | --- | --- |
| 그림자 | `--shadow-1/2/3` | `--shadow-sm/md` | **이름을 시안대로 되돌림** |
| 포커스 색 | `--color-border-focus` | `--color-focus-ring` | 이름은 시안대로, 값만 유지 |
| 다크 모드 | `[data-theme="dark"]` 전체 | 없음 | **통째로 가져옴** |
| 폰트 토큰 | `--font-sans`, `--font-mono` | 없음 | 추가 |
| Pretendard | CDN 로드 | 안 함(폴백만) | 시안과 같은 CDN 연결 |
| 숫자 정렬 | `font-feature-settings:"tnum"` | 없음 | 추가 |
| body 배경 | `--color-bg-sunken` | `--color-bg` | 시안대로 |
| `--radius-xl` | 16px | 없음 | 추가 |
| 링크 색 | `primary-500` + hover 밑줄 | `inherit` | 시안대로 |

**포커스 색만 값을 다르게 유지했다.** 시안은 `--color-border-focus`가 `--color-primary-500`과
같은 값인데, 그러면 primary 버튼 위에서 포커스 링이 안 보인다([[시안 검수 결과]] 8번).
이름을 바꾸면 대조가 안 되므로 **이름은 시안 그대로 두고 값만** secondary 계열로 바꿨다.

## C-04 갤러리 — 고침 (2026-07-26)

시안 상태 8개: 기본 · 로딩 · 추가 로딩 · 0건 · 이미지 실패 · 삭제된 항목 · 휴면 시공자 · 비로그인 컨택

| 시안 | 조치 |
| --- | --- |
| 공종 칩 + **지역 칩** 2줄 필터 | ✅ 추가. 두 축이 서로를 지운다 — 한쪽을 눌러도 반대쪽 선택이 URL에 남는다 |
| `12건 · 최근 시공순` | ✅ 추가. API에 `totalCount` 를 새로 넣었다 |
| 카드 사진 위 공종 뱃지(좌상단, 불투명 흰 칩) | ✅ |
| 카드 사진 위 `8장` 뱃지(우하단, scrim) | ✅ |
| 카드 한 줄 `성북구 24평 · 김도배` | ✅ **시공자 이름을 넣었다** |
| 카드 `--radius-md`, 제목 14px/700, 메타 12px tertiary | ✅ |
| 칩 높이 36px · `--color-border-strong` · 600 · 가로 스크롤 | ✅ |
| 빈 상태 2갈래 | 유지 — 시안보다 나은 부분이다 |
| 이미지 실패 · 삭제된 항목 · 휴면 시공자 상태 | 아직 없음 |

**승인 뱃지·경력·비용공개 뱃지 줄은 뺐다.** 내가 시안을 안 보고 넣었던 것이다.
갤러리에 뜨는 항목은 공개 조건 두 개를 이미 통과했으므로 **전부 승인된 것**이다 —
모두에게 붙는 뱃지는 정보량이 0이고 시안이 말한 "UI 크롬 최소"를 깬다.
[[시안 검수 결과]] 10번이 요구한 "사람을 판단할 근거"는 시안이 이미 메타 줄에
시공자 이름으로 넣어뒀다. 내가 시안을 안 봐서 별도 줄을 만들었던 것뿐이다.

`totalCount` 는 **첫 페이지에서만** 센다. COUNT 는 조건에 맞는 행을 전부 훑으므로
페이지를 넘길 때마다 하면 목록이 느려진다. 수만 건이 되면 근사치나 캐시로 바꾼다.

## G-01 랜딩 — 고침 (2026-07-26)

시안 상태 5개: 기본 · 로딩(스켈레톤) · 빈 상태(콜드스타트) · 이미지 에러 · 로그인 상태

구현했던 랜딩은 히어로 한 덩어리와 공종 칩이 전부였다. 시안의 절반 이상이 없었다.

| 시안 | 조치 |
| --- | --- |
| 아이라벨 `반셀프 인테리어 · 공종 직거래` | ✅ |
| H1 `종합업체 없이, 사진으로 시공자를 직접 고릅니다` | ✅ 시안 문구 그대로 |
| 통계 3칸 | ✅ **콜드스타트에서 문구가 통째로 바뀐다**(아래 참고) |
| 공종 칩 가로 스크롤 | ✅ |
| 최근 시공 그리드 6장 + `전체 보기` | ✅ 갤러리 API를 SSR에서 부른다 |
| `3단계로 끝납니다` | ✅ 번호 원 + 제목 + 설명 |
| **푸터 통신판매중개자 고지** | ✅ **추가 — 법적 요구인데 통째로 없었다** |
| 시공자 카드 예시 블록 | ❌ 실제 데이터가 아니라 예시라서 뺐다 |
| 로딩 스켈레톤 | ❌ SSR이라 로딩 상태가 없다 — 서버가 완성된 HTML을 준다 |

### 콜드스타트에서 숫자를 쓰지 않는다

시안의 콜드스타트 상태가 이 화면의 핵심이다.

| | 콘텐츠 있음 | 콘텐츠 0건 |
| --- | --- | --- |
| 통계 1 | `6건 · 등록된 시공 사진` | `중간 마진 0원 · 일감비만 지불` |
| 통계 2·3 | 가치 제안 그대로 | `서울 4개 구` · `무료` |
| 그리드 | 최근 시공 6장 | `첫 시공자를 모집하고 있습니다` + CTA 2개 |
| 제목 | `최근 올라온 시공` | `곧 채워집니다` |

**"0건"은 안 쓰느니만 못하고 "6건"도 초라하다.** 그래서 콘텐츠 양과 무관하게 항상
참인 것(중간 마진 0원, 무료, 서비스 지역)으로 바꾼다. [[리스크 - 콜드스타트]]의 대응이
화면에 그대로 구현된 지점이다.

DB에서 포트폴리오를 전부 숨겨 두 상태를 실제로 확인했다.

**푸터는 랜딩이 아니라 레이아웃에 뒀다.** 통신판매중개자 고지는 어느 화면에서 들어오든
보여야 한다. 시안은 랜딩에만 그렸지만 그건 시안이 랜딩 화면이기 때문이다.

시안의 `312명 인증 시공자`·`평균 4시간 첫 제안까지`는 못 넣었다 — 승인 시공자 수와
응답 시간 집계 API가 없다. 랜딩 통계만을 위해 API를 만드는 건 아직 과하다고 봤다.

## G-03 역할 선택 온보딩 — 고침 (2026-07-26)

시안 상태 6개: 기본(미선택) · 선택됨 · 시공자 선택 · 이탈 후 재진입 · 확정 중 · 확정 실패

| 시안 | 조치 |
| --- | --- |
| 제목 `어느 쪽으로 시작하시겠어요?` | ✅ 시안 문구 그대로 |
| 카드마다 **불릿 3개** — 그 역할이 뭘 하게 되는지 | ✅ **추가.** 없었다 |
| 카드마다 **`다음 화면:` 안내** | ✅ **추가.** 고르기 전에 뭘 하게 될지 안다 |
| 시공자 카드 승인 절차 고지(사업자등록증 · 1영업일) | ✅ **추가** |
| 하단 `한 번 고르면 스스로 바꿀 수 없습니다` 블록 | ✅ **버튼 바로 위에** 뒀다 — 설명 문단에 섞으면 안 읽는다 |
| 미선택 시 버튼 `역할을 하나 골라주세요` + 헬퍼 | ✅ 잠긴 이유를 말한다 |
| 라디오 점(24px) | ✅ 색만으로 알리지 않는다 |
| `role="radiogroup"` / `role="radio"` | ✅ 둘 중 하나라는 걸 스크린리더도 안다 |

### 잡은 버그 — 시공자를 골라도 홈으로 튕겼다

`selectProfile()` 이 성공하면 `user.profileType` 이 채워지고, 그러면 "이미 역할이 있으면
되돌아간다"는 `useEffect` 가 발동해 **confirm 쪽의 이동을 덮어썼다.** 카드에는
"다음 화면: 프로필 등록"이라고 써놓고 실제로는 홈으로 보냈다.

이동 지점을 `useEffect` 한 곳으로 모아서 고쳤다. 두 곳에서 이동시키면 반드시 경쟁한다.
두 역할 모두 실제로 가입해서 도착 지점을 확인했다 — 시공자 `/portfolios/new`,
고객 `/requests/new`.

### 서버가 주는 `next` 를 쓰지 않았다

`POST /me/profile` 응답은 시공자에게 `/pro/profile` 을 준다. **그 화면은 구현도 없고
시안도 없다** — `design/` 에 시공자 프로필 등록 시안이 아예 없다.
지금은 실제로 존재하고 시공자가 바로 할 일인 `/portfolios/new` 로 보낸다.
프로필 등록 화면을 만들 때 서버 응답과 화면 경로를 다시 맞춰야 한다.

## C-01 의뢰 등록 — 고침 (2026-07-26)

시안 상태 6개 × 4스텝: 기본 · 업로드 중 · 업로드 실패 · 사진 0장 · 임시저장 복원 · 제출 중

**구현은 한 페이지 긴 폼이었다.** 시안은 4단계 마법사다. 구조가 통째로 달랐다.

| 시안 | 조치 |
| --- | --- |
| 4단계: 사진 → 공종 → 조건 → 확인 | ✅ **다시 만들었다** |
| `1 / 4 단계` + 진행 막대 | ✅ 4단계라는 걸 처음부터 보여줘야 중간에 안 나간다 |
| **제목을 묻지 않고 자동 생성** | ✅ `성북구 24평 도배+장판·마루` — 아래 참고 |
| 스텝 넘길 때 임시저장 + `HH:MM 임시저장됨` | ✅ DRAFT 를 만들기만 하고 사용자에게 안 알렸었다 |
| 저작권 고지 문구 | ✅ 사진 단계에 배치 |
| 사진 `대표` 뱃지 · `N장 · 첫 번째 사진이 대표로 쓰입니다` | ✅ |
| 희망 시기를 칩으로 | ✅ **상대 기간으로 바꿨다** — 아래 참고 |
| 4단계 요약(대표 사진 + 항목별 칸) | ✅ |
| `이름·연락처·상세 주소는 컨택을 수락한 시공자에게만` | ✅ 등록 버튼 바로 위 |
| 못 넘어갈 때 이유 표시 | ✅ 시안보다 명시적으로 |
| 데스크톱 좌측 스텝 사이드바 | ❌ 진행 막대로 대체 |
| 우측 고정 `시공자에게는 이렇게 보입니다` | ❌ 4단계 요약에 흡수 |
| 사진 순서 바꾸기 | ❌ 드래그 정렬은 아직 |

### 제목을 묻지 않는다

시안에 **제목 입력 칸이 없다.** 대신 `성북구 24평 도배+바닥·장판` 처럼 조합해서 쓴다.

고객은 의뢰 제목을 어떻게 써야 할지 모른다. 빈 칸을 주면 "도배요"라고 쓰거나 아예 비운다.
지역·평수·공종을 조합하면 시공자가 목록에서 훑기에도 형식이 일정하다.
구현은 제목 칸을 받고 있었다 — 시안을 안 본 결과다.

### 희망 시기는 상대 기간으로 바꿨다 — 의도된 차이

시안은 `2주 이내 / 8월 초 / 8월 중순 / 미정` 이다. **`8월 초` 같은 절대 표현은 시간이
지나면 과거가 된다.** 시안은 한 시점의 그림이라 괜찮지만 코드는 계속 돈다.
`2주 이내 / 1개월 이내 / 3개월 이내 / 미정` 으로 바꾸고 날짜는 오늘 기준으로 계산한다.

### 사진별 출처는 시안에 없다 — 의도된 차이

시안은 `직접 촬영했거나 사용 권리가 있는 사진입니다` 한 문장으로 선언한다.
구현은 **사진마다** SELF/EXTERNAL 을 받고 EXTERNAL 이면 원본 주소를 요구한다.
시안이 만들어진 뒤에 [[리스크 - 레퍼런스 사진 저작권]] 대응이 강화됐고 DB CHECK 제약까지
걸렸다. **구현이 시안보다 엄격한 쪽이므로 유지한다.**

### 타이포는 크기만 변수로 두면 또 갈라진다

시안의 한 행은 `40/800/1.2/-0.03em` 네 값이다. 크기만 토큰으로 만들면 굵기·행간·자간을
화면에서 다시 정하게 되고 그러면 대조가 안 되는 건 똑같다. 그래서 **네 값을 묶은
`.t-display` ~ `.t-caption` 클래스**를 두고 화면은 클래스만 쓴다.

토큰 이름은 시안이 이미 02 TYPE 표에 적어둔 것(`--text-h1` 등)이고 푸터의 토큰 집계도
`type 6` 이라고 세고 있었다. **선언만 빠져 있었다.** 그래서 시안 `:root` 에 6줄을 추가하고
사본으로 가져왔다 — QC 의 `token-invented` 가 요구하는 "시안에 먼저 넣고 가져와라" 순서다.

### `button { min-height:44px }` 를 걷어냈다

전역으로 44px 을 강제하고 있었는데 **그게 시안을 어기고 있었다.** 시안의 칩은 36px,
sm 버튼은 32px 인데 전부 44px 로 부풀어 있었다. 시안이 정한 규칙은 "**모바일** 최소
터치 타깃 44px"이고 그래서 모바일 주 버튼이 48~52px 다. 크기는 컴포넌트가 정한다.

### 폭을 세 종류로 줄였다

`max-width` 가 680 · 720 · 880 · 1120 으로 제각각이었다. 화면을 넘어갈 때마다 본문이
좌우로 흔들린다. `.shell`(1280 · 시안의 데스크톱 프레임) · `.shell--content`(1000) ·
`.shell--form`(680) 셋만 남겼다. 셋 다 시안에 실제로 있는 값이다.

### `pnpm qc` 에 타이포 검사를 넣었다

`fontSize: 24` 같은 하드코딩을 잡는다. **지금은 warn 이고 101건이다** — 화면별 대조가
끝날 때마다 줄어든다. 마지막 화면을 옮기는 순간 error 로 올린다. 지금 error 로 두면
그 화면을 손대지 않는 커밋까지 전부 막힌다.

12px 이하는 검사 대상이 아니다. 시안 자체가 뱃지·오버레이 칩에 10~12px 를 직접 쓰고
스케일에 그 단이 없다 — 스케일에 없는 걸 스케일로 쓰라고 할 수는 없다.

### 시안 두 개가 서로 다른 말을 한다 — 화면 시안을 택했다

디자인 시스템의 `display` 는 40px(모바일 32)이고 용도를 "랜딩 히어로 1개"라고 못 박았는데
**G-01 의 h1 은 52px** 이다. 섹션 제목도 스케일의 h2(22px)가 아니라 26px 다.

**화면 시안을 따랐다** — 사용자가 비교하는 건 그 화면이다. 대신 숫자를 tsx 에 흩뿌리지 않고
`components.css` 의 `.landing-*` 한 곳에 모았다. 시안끼리 어긋난다는 사실은
[[시안 검수 결과]] 11번에 결함으로 올렸다.

### 로그인 상태 배너는 개수가 내용이다

시안이 "마케팅 히어로 위에 지금 처리할 일 배너를 얹는다"고 한 게 이 상태다.
이름만 띄우면 배너가 아무 일도 하지 않으므로 **답하지 않은 문의 수(REQUESTED)를 센다.**
랜딩은 SSR 인데 이 조각만 클라이언트다 — 액세스 토큰이 브라우저 메모리에만 살아서
서버는 누가 보고 있는지 알 수 없다.

세는 중에는 "확인하고 있습니다"라고 쓴다. 숫자 자리에 0 을 먼저 넣으면 잠깐 거짓말을 한다.

### 시공자 카드는 시안의 가짜 데이터를 실제 데이터로 바꿨다

시안은 `김도배 · 경력 11년 · 시공 87건` 을 그려뒀다. 그대로 옮기면 **랜딩에 없는 실적을
적는 것**이 되므로 가장 최근 사례의 시공자·실제 경력·실제 활동 지역·실제 사진으로 그린다.
시공 건수와 평균 응답 시간은 집계 API 가 없어서 뺐다 — 없는 숫자를 지어내는 것보다
있는 것만 보여주는 쪽이 이 섹션의 주장("판단에 필요한 것만 앞에 둔다")에 맞다.

콜드스타트에서는 이 섹션을 통째로 숨긴다. 보여줄 실제 시공자가 없다.

### 이미지 에러는 사진 한 장 단위로 다룬다

시안: "카드 자리는 유지하고 재시도 버튼을 준다. 레이아웃은 흔들리지 않는다."
`PhotoImg` 가 `onError` 를 받아 그 자리에 안내 + `다시 시도` 를 그린다. 브라우저에서
실제로 src 를 깨뜨려 확인했다 — **카드 높이가 211.7px 그대로 유지되고** 제목·메타는 살아 있다.

재시도는 쿼리스트링을 붙여 다시 요청한다. 같은 URL 로 다시 그리면 브라우저가 실패한 응답을
캐시에서 꺼내서 아무 일도 일어나지 않는다. 그리고 **카드 전체가 링크라서 클릭 전파를 막는다** —
안 막으면 재시도를 누른 사람이 상세로 넘어간다.

### 콜드스타트 CTA 순서를 뒤집었다

시안이 요구한 것이다. 사진이 없는 상태에서 고객을 데려와도 보여줄 게 없다 — 공급이 먼저다.
브라우저에서 두 상태를 다 확인했다.

### `더 보기` 를 만들면서 첫 페이지는 SSR 로 남겼다

갤러리가 **유일한 유입 통로**라 색인을 잃으면 안 된다. 그리드를 클라이언트 컴포넌트로
바꿨지만 서버가 첫 페이지를 그려서 넘기므로 초기 HTML 에는 카드가 그대로 들어 있다.

브라우저에서 실제로 확인했다. 페이지 크기를 2로 줄여놓고 세 번 눌러 6건을 다 불러왔고,
**기존 카드가 그대로 있고 중복이 없고 마지막에 버튼이 사라지는 것**까지 봤다.

### 모바일에서 제목을 지웠지만 문서에서는 지우지 않았다

시안의 모바일 갤러리는 제목이 없다 — 390px 에서는 사진이 먼저다. 그런데 `display:none`
으로 지우면 **문서에 h1 이 없어진다.** 그래서 `.hide-on-mobile`(clip-path)로 눈에서만
치웠다. 브라우저에서 h1 이 1px 박스이면서 텍스트가 살아 있는 걸 확인했다.

### 시공자 카드를 고정한 이유

상세는 **컨택 직전 화면**인데 1단 레이아웃에서는 시공자 카드가 스크롤 맨 아래 있었다.
사진이 8~11장인 사례에서 그건 이 화면의 목적을 화면 밖에 두는 것이다.
데스크톱은 우측 372px 에 고정하고 모바일은 하단 고정 CTA 로 같은 문제를 푼다.

### 사진이 2장이면 시안의 모자이크가 성립하지 않는다

시안 배치(큰 것 1 + 작은 것 2)를 그대로 쓰면 2장짜리 사례에서 **큰 칸과 작은 칸에 같은
사진이 걸린다.** 브라우저에서 실제로 그렇게 나왔다. 1장이면 통째로, 2장이면 반씩 나눈다.

같은 자리에서 하나 더 고쳤다 — **작은 칸에도 단계(시공 전/후) 칩을 넣었다.** 큰 칸에만
라벨이 있으면 나란히 걸린 옆 사진이 무엇인지 알 수 없고, before/after 대비는 이 서비스에서
실력을 가장 잘 보여주는 장치다.

### 삭제된 항목은 404 를 유지하되 막다른 길로 두지 않았다

시안은 SEO 링크가 남으므로 404 대신 설명 화면을 주라고 한다. 맞는 지적이지만 그러려면
API 가 "있었지만 내려갔다"를 구분해 알려줘야 하고, 그 구분은 곧 "그 항목은 존재한다"가
새는 것이다. 비공개로 돌린 사람의 선택을 뒤집는 셈이다.

그래서 `not-found.tsx` 로 **이유는 구분하지 않되 다음 행동은 주는** 화면을 만들었다.
문구가 "내려갔습니다"가 아니라 "볼 수 없습니다"인 건 어느 경우에도 참인 말이기 때문이다.

### 비로그인 컨택은 인라인 시트를 만들지 않았다 — 의도된 차이

시안은 상세에서 로그인 시트를 띄운다. 갤러리는 SSR 이라 **서버가 로그인 여부를 모른다**
(액세스 토큰이 브라우저 메모리에만 산다). 판단을 클라이언트 화면 한 곳(`/contacts/new`)에
몰아두는 기존 결정을 유지했다. 시안의 `카카오로 3초 만에 시작` 은 그 로그인 수단이 없다.

### 자재 등급 문구는 `packages/shared` 로 갔다

시안은 등급 버튼을 두 줄로 그리고 아래 줄에 `가성비 / 무난 / 마감 중시` 를 붙인다.
`보급/중급/고급` 만 보여주면 고객은 무엇을 고르는지 모른다 — 자재 등급은 인테리어 용어를
모르는 사람이 가장 먼저 막히는 칸이다.

이 문구를 화면에 적지 않고 `MATERIAL_GRADE_HINTS` 로 라벨 옆에 뒀다. 화면마다 갈라지면
같은 등급이 화면에 따라 다른 뜻으로 읽힌다.

### 스텝 사이드바는 지나온 단계까지만 누를 수 있다

시안의 스텝 버튼은 아무 데나 갈 수 있지만 그건 시안이 검증 없는 그림이기 때문이다.
앞 단계로 건너뛰게 하면 **사진 0장짜리 의뢰가 등록될 수 있다.** 지나온 단계와 현재
단계만 활성이다. 현재 단계를 잠그지 않은 이유는 어디까지 갈 수 있는지가 흐려지기 때문이다.

### 임시저장 복원 배너는 만들지 않았다

시안의 6상태 중 `임시저장 복원`("작성 중이던 의뢰가 있습니다 · 이어서 작성 / 새로 시작")만
빠졌다. 지금 구현은 **화면에 들어올 때마다 새 DRAFT 를 만든다.** 복원을 하려면 서버가
"이 사용자의 미완성 DRAFT" 를 찾아 돌려주는 조회가 필요하고, 그건 API 변경이다.

그대로 두면 나갔다 들어올 때마다 빈 DRAFT 가 쌓인다 — 다만 고아 DRAFT 는 이미
정리 배치가 치우고 있으므로 새는 건 없다. [[열린 질문]] Q9 로 올렸다.

### 브라우저에서 4단계를 끝까지 통과시켰다

사진을 실제로 주입해서 서명 URL → 업로드 → 사진별 출처까지 태웠다. 확인한 것들:

- 사진 0장에서 `다음` → `사진을 최소 한 장 올려주세요.` (CTA 옆, `role=alert`, danger 색)
- 출처 기본값 EXTERNAL 이라 원본 주소 없이는 못 넘어간다 — `남의 사진에는 원본 주소가 필요합니다.`
- 스텝을 넘길 때 `오후 03:44 임시저장됨` 이 상단에 뜨고 지나온 단계에 `✓` 가 붙는다
- 진행률 25% → 50% → 75% → 100%
- 평수 24 를 넣으면 `약 79.3㎡` 가 힌트에 뜬다(서버 파생과 같은 상수)
- 4단계 요약 6줄이 전부 실제 입력값으로 채워진다

### 목록·상세를 나란히 둔 이유

시안의 데스크톱은 왼쪽 392px 이 목록이고 오른쪽이 상세다. 구현은 두 페이지가 완전히
분리돼 있어서 **컨택을 하나 처리할 때마다 목록으로 돌아갔다 다시 들어와야 했다.**
받은 문의가 5건이면 그게 전부 왕복이 된다.

`/contacts` 와 `/contacts/[id]` 가 같은 레이아웃을 쓰고 오른쪽만 다르다.
목록만 있을 때 오른쪽은 "컨택을 고르면 여기에 열립니다" 다. 모바일은 시안대로
한 번에 하나만 보인다 — 390px 에 두 판을 넣을 수 없다.

### 타임라인이 상태 뱃지보다 많은 걸 말한다

`요청 → 응답 → 연락처 공개` 세 칸이고 지나온 칸은 primary 점, 남은 칸은 빈 점이다.
`응답` 칸이 대기 중이면 `대기 중 · 2026. 8. 2. 만료` 라고 적는다.

상태 뱃지 하나로는 **지금 무엇을 기다리는지**가 안 보인다. 이 서비스의 컨택은
"수락하면 연락처가 열린다"가 전부인데 그 인과가 화면에 없었다.

### 연락처는 공개 전에도 자리를 보여준다

전에는 `phone` 이 있을 때만 블록이 나타났다. 그러면 수락을 판단하는 시점에
**무엇이 열리는지가 화면에 없다.** 지금은 점선 상자에 `010-••••-••••` 를 두고
"수락하면 양쪽 연락처가 동시에 열립니다. 그 전까지는 서버 응답에도 연락처가 들어
있지 않습니다"라고 적는다.

**마스킹은 화면의 표현일 뿐이고 판단은 그대로 서버가 한다** — 화면은 `phone` 키가
있는지 없는지만 본다. 마스킹된 값을 받아서 가리는 구조였다면 이 보장이 없다.

### `window.prompt` 를 걷어냈다

거절 사유를 브라우저 기본 대화상자로 받고 있었다. 시안은 인라인 시트를 요구한다 —
"종료 상태로 가는 전이는 되돌릴 수 없으므로 한 번 더 묻고, 사유는 선택으로 받는다."

`window.prompt` 에는 **되돌릴 수 없다는 경고를 담을 자리가 없고** 사유 보기를 줄 수도 없다.
보기 3개(`일정이 맞지 않음` · `활동 지역 밖` · `공종이 맞지 않음`)는 `DECLINE_REASONS` 로
`packages/shared` 에 뒀다 — 상대에게 그대로 보이는 문구다. 서버는 여전히 자유
문자열을 받는다. 보기는 편의이고 강제가 아니다.

### 브라우저에서 확인한 것

실제로 문의를 하나 보내고(서명 없이 폼으로) 확인했다.

- 목록 2단 `392px / 873px`, 선택한 행이 primary-50 으로 표시된다
- 타임라인 3칸 · 1칸 완료 · `대기 중 · 2026. 8. 2. 만료`
- 요청자에게는 **`요청 취소` 만** 보인다 — 수락·거절 버튼이 렌더되지 않는다
- 거절 시트: danger 테두리 · 사유 3개 · `돌아가기` / `거절하기`, 여는 동안 위쪽 액션은 사라진다
- **버튼을 감추는 건 친절이고 판단은 서버가 한다** — 요청자가 거절을 시도하면
  `이 동작을 할 수 있는 사람이 아닙니다` 로 막히고 상태는 그대로 REQUESTED 다
- 필터 0건과 진짜 0건이 다른 문구다
- 모바일에서는 목록·상세가 갈리고 `← 컨택 목록` 이 나타난다

수신자 화면(수락/거절)은 **데모 시공자 계정에 비밀번호가 없어서**(로그인 가능한 데모
계정은 뒷문이다) 임시 플래그로 렌더만 확인했다. 서버 가드는 위처럼 실제로 걸어봤다.

### 경계를 하나 틀렸다가 잡았다

액션 자리를 데스크톱/모바일로 나누면서 일반 유틸리티(`.hide-on-mobile`, 768px)를 썼는데
이 화면은 **900px 에서 갈라진다.** 768~900px 구간에서 버튼이 두 벌 보였을 것이다.
같은 화면의 두 요소는 같은 경계를 써야 한다 — 화면 전용 클래스로 바꿨다.

### `StatusChip` 을 지웠다

`.badge` 프리미티브가 같은 일을 하고 색 규칙도 디자인 시스템 정본을 따른다.
쓰는 곳이 없어진 컴포넌트를 남겨두면 다음 사람이 둘 중 뭘 쓸지 고민한다.

| **자재 등급 2줄 카드 64px** | 셀렉트 | ✅ |
| **동의 체크박스가 관문** | 없었다 | ✅ 아래 참고 |
| **`비공개로 저장`** | 없었다 | ✅ 아래 참고 |

| 모바일 하단 고정 바 | 없음 | ✅ |

| `프로필 완성도` | — | ❌ 아래 참고 |

### ⚠️ 화면이 서버보다 무른 말을 하고 있었다

**가장 중요한 발견이다.** 화면은 "공개해도 승인 전에는 갤러리에 안 뜬다"고 말했는데
실제로 눌러보니 서버가 **공개 자체를 막는다** — `POST /portfolios/:id/publish` 는
승인된 시공자 전용이고 `관리자 승인 후에 이용할 수 있습니다` 로 403 이 온다.
컨트롤러에 `/** 미승인 시공자는 여기서 403이다. */` 라고 적혀 있다.

즉 미승인 계정에게 `사례 공개하기` 버튼은 **누를 때마다 실패하는 버튼**이었다.
1차 대조 노트도 같은 오해를 적고 있었고 `내 사례` 화면 배너도 같은 문구였다.

셋 다 고쳤다.
- 안내: "승인 전에는 공개할 수 없습니다 · 지금 비공개로 저장해두면 승인 즉시 공개할 수 있습니다"
- 버튼: 미승인이면 공개 버튼을 두지 않고 `비공개로 저장` 을 주 행동으로 올린다
- `내 사례` 배너도 같은 말로 통일

**브라우저에서 실제로 눌러보지 않았으면 못 찾았을 종류다.** 타입도 테스트도 통과한다.

### 프로필이 없으면 승인도 없다 — 상태를 셋으로 나눴다

`/me/pro-profile` 은 프로필이 없으면 404 다. 방금 시공자를 고른 계정이 그렇다.
`unknown`(못 읽음) · `none`(프로필 없음) · `pending` · `approved` 넷을 구분한다.
**`none` 과 `pending` 은 다음 할 일이 다르다** — 앞은 프로필을 만들어야 하고 뒤는 기다리면 된다.
"기다리세요"라고만 쓰면 프로필이 없는 사람은 영원히 기다린다.

`unknown` 일 때는 버튼을 감추지 않는다. 모르는 걸 단정하지 않는다.

### 잡은 버그 — 초안 생성이 프로필 조회를 취소하고 있었다

프로필 조회를 초안 생성과 같은 effect 에 뒀더니, 초안이 만들어져 `draftId` 가 바뀌는
순간 effect 가 다시 돌고 그 정리 함수가 `alive = false` 를 만들어 **아직 날아오는 중이던
프로필 응답을 통째로 버렸다.** 상태가 영원히 `unknown` 에 머물러서, 공개할 수 없는
계정에 공개 버튼이 그대로 남아 있었다.

화면에 상태를 `data-` 속성으로 찍어보고 나서야 알았다. effect 를 분리해 고쳤다.

### 동의 체크박스는 여기서는 진짜 관문이다

C-01 에서는 **사진마다** 출처를 받으므로 시안의 체크박스를 대체했다. 포트폴리오는
시공자 본인 작업물을 전제해서 사진별 출처가 없다 — **그래서 이 체크가 유일한 관문이고**
체크 없이는 공개할 수 없다. 안 하고 누르면 상자 자체가 붉어진다(테두리 + 배경).

### `비공개로 저장` 은 사진 15장을 지키는 버튼이다

시안이 이 버튼을 왼쪽에 따로 둔 이유가 있다. 사진 15장을 올리다 말면 그 업로드가 전부
헛일이 된다. DRAFT 로 남기면 이어서 할 수 있다. 공개가 아니므로 검증도 걸지 않는다 —
미완성이 DRAFT 의 정의다.

### `프로필 완성도` 는 만들지 않았다

시안은 "포트폴리오 3건을 넘기면 목록 상단 노출 대상이 됩니다"라고 쓴다.
**그런 랭킹 규칙이 없다.** 없는 규칙을 화면에 적으면 그건 지키지 못할 약속이다.
그 자리에 실제로 참인 것(공개 조건)을 넣었다.

### QC 가 오탐이 나서 검사기를 고쳤다

숫자 인풋의 플레이스홀더를 `24평` 으로 썼더니 확장 규약 1조 위반으로 잡혔다.
**지적이 맞았다** — 숫자 칸인데 단위까지 칠 수 있는 것처럼 보인다. 단위는 라벨로 옮겼다.

고치고 나서도 계속 잡혔는데 이번엔 오탐이었다. 검사기가 **줄 단위**로 보는데 Prettier 가
JSX 속성을 여러 줄로 쪼개서 `<input` 과 `type="number"` 가 다른 줄에 산다.
태그가 닫힐 때까지 이어 붙여서 보게 고쳤고, "이 인풋이 평수인가"를 라벨뿐 아니라
**인풋 자신의 `aria-label`** 로도 판단하게 했다 — 줄 수에 기대는 판정을 하나 줄였다.
**일부러 `type="text"` 로 바꿔 검사기가 여전히 잡는 것을 확인했다.**

## G-03 역할 선택 온보딩 — 2차 대조 (2026-07-26)

1차에서 **내용은** 다 맞췄다(불릿 3개·다음 화면 안내·승인 고지·되돌릴 수 없음·radiogroup).
남은 건 **크기와 정렬**이었다. 구현은 760px 왼쪽 정렬에 h1 26px 이라
"설정 페이지 한 칸"처럼 보였고, 시안은 화면 한가운데에 크게 두 장을 놓는다.

| 시안(데스크톱) | 1차 구현 | 조치 |
| --- | --- | --- |
| 가운데 정렬 · padding 56/40/48 · gap 28 | 760px 왼쪽 정렬 | ✅ |
| h1 **38px**/-0.03em · 리드 17px | 26px · 16px | ✅ |
| 카드 가로 2장 · max 880 · gap 20 | `auto-fit minmax(280px)` | ✅ |
| 카드 padding **26** · 제목 **22** · 리드 16 · 불릿 15 | 18 · 19 · 15 · 14 | ✅ |
| 선택 시 **2px** 테두리 + primary-50 + shadow-1 | 1px 테두리 | ✅ 아래 참고 |
| 라디오 점 = **7px 링** | 안쪽 그림자 방식 | ✅ |
| 승인 고지를 **warning 상자**로 | 평문 12px | ✅ |
| CTA **56px · 최소 320px · 18px** 가운데 | 전폭 48px | ✅ |
| 되돌릴 수 없음: CTA **아래** 한 문장 | CTA 위 상자 | ✅ 모바일은 시안대로 상자 유지 |

| 모바일 하단 고정 CTA + 잠긴 이유 | 본문 안 버튼 | ✅ |
| 확정 실패 시 `다시 시도` 버튼 | `FormError` | 유지 — 같은 버튼을 다시 누르면 된다 |

### 선택 표시를 두께로 바꾸면서 카드 크기를 지켰다

시안은 고른 카드의 테두리를 1px → 2px 로 굵힌다. 색만 바꾸면 색각 이상에서 약하고,
라디오 점 하나로는 카드 두 장 중 어느 쪽인지 훑어서 안 보인다.

다만 테두리가 굵어지면 카드가 1px 커져서 **옆 카드와 높이가 어긋난다.** 안쪽 패딩을
26 → 25 로 줄여 상쇄했다. 브라우저에서 두 카드 높이가 같은 것을 확인했다.

### 이탈 후 재진입 배지는 `next` 파라미터로 판단한다

역할이 없으면 어떤 경로로 들어와도 이 화면으로 되돌린다. 그때 `next` 가 붙는다 —
그게 곧 "보호된 화면에서 튕겨왔다"는 신호다. 강제하되 이유를 말한다.

### ⚠️ 잡은 버그 — 역할을 골랐는데 아무 데도 도착하지 못한다

`/portfolios/new`(시공자 전용)에서 튕겨온 사람이 **고객**을 고르면 `next` 를 그대로 따라
다시 `/portfolios/new` 로 갔고, 그 화면의 역할 가드가 또 홈으로 튕겼다.
**브라우저에서 실제로 그렇게 됐다** — 역할을 고르고 나서 원하지도 않은 곳으로 밀린다.

역할에 안 맞는 `next` 는 버리고 그 역할의 착지점으로 보낸다.
`/portfolios*` 는 시공자, `/requests*` 는 고객, 나머지(`/contacts`·`/gallery`)는 공용이다.

이건 1차에서 고친 버그("시공자를 골라도 홈으로 튕겼다")와 **같은 종류**다 —
이 화면을 떠나는 경로가 여럿이면 서로 다른 곳을 가리킨다. 이동 지점은 하나로 모았지만
그 하나가 계산하는 목적지가 틀렸던 것이다.

## P-04 · P-05 의뢰 목록·상세 — 새로 만듦 (2026-07-26)

**이 화면이 없어서 서비스가 한쪽으로만 돌고 있었다.** 고객이 의뢰를 올려도 시공자가
볼 방법이 없었다 — `GET /reference-requests` 는 진작 있었는데 화면이 없었다.

경로는 `/jobs`, `/jobs/[id]` 다. 시공자 헤더에 `의뢰 찾기` 를 첫 메뉴로 넣었다.

### P-04 목록

시안대로 좌측 272px 필터 + 본문이다. 카드는 **사진이 왼쪽에 작게** 붙고 글이 주인공이다 —
시안이 적어둔 이유가 이것이다: "시공자는 현장에서 폰으로 훑는다. 카드 한 줄에
지역·평형·공종·시기가 다 있어야 스크롤만으로 판단이 끝난다."

- 뱃지 3종: 공종 · `신규`(24시간 이내) · **`제안 0건`**
- `제안 0건` 은 경고가 아니라 **기회**다. 경쟁이 없다는 뜻이라 시공자가 제일 먼저 본다.
  반대로 5건이면 안 쓸 수도 있다 — 어느 쪽이든 판단 근거다.
- 빈 상태를 두 갈래로(필터 0건 / 아직 아무 의뢰도 없음). 갤러리와 같은 원칙이다.
- 첫 진입 스켈레톤. 필터는 즉시 렌더돼서 로딩 중에도 조건을 바꿀 수 있다.

**`내 활동 지역만` 체크박스는 버튼으로 바꿨다.** 시안은 체크박스지만 우리 필터는
URL 에 사는 지역 코드 목록이다 — 체크박스를 따로 두면 상태가 둘이 되고 갈라진다.
`내 활동 지역만 보기` 버튼이 프로필의 `serviceAreas` 로 그 목록을 채운다. 결과는 같고
상태는 하나다.

### P-05 상세

본문 + 우측 372px **고정** 제안 패널이다. 사진과 조건을 훑는 동안 제안 수단이
화면에서 사라지면 안 된다.

- **미승인이면 제안만 잠긴다.** 열람까지 막으면 승인을 기다릴 동기가 사라진다(시안 판단).
  텍스트영역·금액·버튼이 전부 잠기고 이유를 상자로 말한다.
- **내 활동 지역 밖이면 알려주되 막지 않는다.** 출장을 갈지는 시공자가 정할 일이다.
  등록된 활동 지역이 없으면 판단하지 않는다 — 모르는 걸 "밖이다"라고 하면 멀쩡한 일감을 놓친다.
- **제안 금액은 선택**이다. 필수로 하면 "현장을 봐야 안다"는 정당한 경우를 막는다.
  그래도 받는 이유는 이게 2차 가격 통계의 1차 데이터원이기 때문이다 —
  거래는 밖에서 성사돼도 제안은 안에서 일어난다([[ADR-010 - 가격 정책 모델]]).
- **중복 제안은 에러가 아니라 상태다.** 서버가 막으면(409) 빨간 글씨 대신
  `제안 보냄 · 응답 대기` 뱃지와 "이미 제안한 의뢰입니다"를 보여주고 컨택으로 보낸다.
  시안의 "이미 제안함"이 이 경우다.

### 고객 신원은 쓰지 않는다 — 시안과 의도된 차이

시안은 `윤지수 고객 · 의뢰 3건 · 컨택 수락률 67%` 를 적는다. 두 가지 이유로 뺐다.
집계 API 가 없고, 무엇보다 **고객 이름은 수락 전에 열지 않는 게 이 서비스의 규칙**이다.
그 자리에 "이름과 연락처는 고객이 제안을 수락한 뒤에 열립니다"를 쓴다 —
이 화면에서 시공자가 알아야 할 것은 고객이 누구인지가 아니라 **언제 알게 되는지**다.

### 브라우저에서 서비스가 한 바퀴 도는 걸 확인했다

고객 계정으로 C-01 을 끝까지 통과시켜 의뢰를 공개하고(`성북구 24평 도배 · 공개 중`),
시공자 계정으로 `/jobs` 에서 그 의뢰를 보고, 상세에서 제안을 보냈다.
`1,800,000원 제안` 이 붙은 컨택 상세로 도착했다.

**고객이 의뢰를 올리면 시공자가 보고 제안한다** — [[진행 현황판]]이 "서비스가 한쪽으로만
돈다"고 적어둔 그 구멍이 닫혔다.

미승인 상태(제안 잠금)와 승인 후(제안 가능), 중복 제안까지 전부 실제로 눌러 확인했다.
승인은 개발 DB 에서 `is_approved` 를 켜서 만들었다 — 관리자 화면은 [[MVP 범위]] 밖이다.

## C-06 · C-07 시공자 목록·상세 — 새로 만듦 (2026-07-26)

**이 화면은 API 도 없었다.** 앞의 여덟과 다르게 화면만 만들 수 없었다 —
`GET /pros`, `GET /pros/:id` 를 새로 만들었다(`apps/api/src/modules/pros/`).

### 없는 숫자는 만들지 않았다

시안의 시공자 카드는 `시공 87건 · 응답 3시간 · 수락률 67%` 를 보여준다.
**그 집계가 하나도 없다.** 그래서 우리가 실제로 아는 것만 쓴다.

| 시안 | 구현 | 왜 |

| `컨택 수락률 67%` | 뺐다 | 같은 이유 |
| 신뢰 지표 3칸 | `등록한 사례 · 경력 · 활동 지역` | 전부 DB 에 있는 값이다 |
| `확인된 정보` 표 | 사업자 확인 · 관리자 승인 · 비용 공개 · **완료 확인·리뷰 `준비 중`** | 없는 걸 "없음"이라고 적는다 |

없는 숫자를 하나 지어내면 그 카드의 나머지도 못 믿게 된다. 이 화면의 목적이
"맡겨도 되는 사람인지 판단"인데 근거가 거짓이면 화면 자체가 무의미해진다.

### 승인 뱃지를 여기서는 단다 — 갤러리와 반대다

C-04 대조 때 "갤러리에 뜨는 항목은 전부 승인된 것이므로 모두에게 붙는 뱃지는
정보량이 0"이라며 뱃지를 뺐다. **이 목록에서는 단다.** 사람을 고르는 화면이라
승인이 첫 번째 판단 근거이고, 카드에 사람의 속성이 몇 개 없기 때문이다.
같은 뱃지가 화면에 따라 정보가 되기도 하고 소음이 되기도 한다.

### 사례가 없는 시공자를 감추지 않는다

시안이 이 상태를 따로 그렸다 — "새로 등록한 시공자입니다. 사업자와 경력은
확인되었지만 시공 사진은 아직 없습니다. 문의하면서 사진을 요청할 수 있습니다."
콜드스타트에서 목록이 비면 안 되고, 새 시공자에게도 노출 기회가 있어야 한다.

### 문의는 사례를 통해서만 보낸다

컨택은 `portfolioItemId` 또는 `referenceRequestId` 에 매달린다 —
**무엇을 보고 연락했는지가 남지 않으면 시공자가 답할 근거도 없다.**
그래서 프로필의 CTA 는 `최근 사례로 문의하기` 이고, 사례가 없는 시공자에게는
`의뢰 올리고 제안받기` 로 바꾼다.

### ⚠️ 잡은 버그 — 같은 사람을 부르는 이름이 둘이었다

새 API 를 `userProfileId` 로 키를 잡았는데 포트폴리오 API 는 `pro.id` 로 **`userId`** 를
쓰고 있었다. 그래서 갤러리 상세에 새로 넣은 `프로필 전체 보기` 링크가 **404** 가 났다.
브라우저에서 눌러보고 알았다.

`userId` 로 통일했다. 새 모듈이 같은 개념에 두 번째 이름을 만들면 안 된다.
**e2e 로 고정했다** — 포트폴리오 API 의 `pro.id` 로 `/pros/:id` 를 부르면 200 이어야 한다.

### 상호가 빈 프로필은 목록에 세우지 않는다

역할을 고르면 프로필 행이 자동으로 생기므로 `businessName` 이 빈 계정이 존재한다.
목록 첫 줄에 **빈 카드**가 떴다. 승인 여부와 무관하게 **아직 등록을 마치지 않은 사람**이고
이름 없는 카드는 고객에게 아무 의미가 없다. 조회 조건에서 뺐다.

(근본 원인은 시공자 프로필 등록 화면이 없다는 것이다 — 시안도 화면도 없다.
G-03 대조 때 적어둔 그 구멍이 여기서 다시 드러났다.)

## 마감 — 타이포 QC 를 error 로 올렸다 (2026-07-26)

**101건 → 0건.** 도입할 때 101건이었고 화면을 하나씩 옮겨 0이 됐다.
0이 된 순간이 잠글 때다 — warn 으로 두면 "나중에"가 계속 미뤄진다.
일부러 `fontSize: 22` 를 넣어 error 로 잡히는 것을 확인하고 되돌렸다.

마지막 29건은 **시안이 없는 화면**들이었다. 시안을 베낄 수 없으니 대신
디자인 시스템 규격 안에서만 만들었다 — 그게 여기서는 "시안을 따르는 것"과 같다.

| 파일 | 무엇을 했나 |
| --- | --- |
| `components/form.tsx` | `.field__label/hint/error` · `.form-error` · `.auth*` 로 옮김. `inputStyle` 삭제 |
| `components/ImageUploader.tsx` | `.uploader__*` 로 옮김. C-01·P-02 가 같은 부품을 쓴다 |
| `내 의뢰` · `내 사례` | `.mine__*` · 제목은 `.t-h1` · 버튼은 공용 `.btn` |
| 로그인 · 가입 · 문의 보내기 | `.auth__foot` · 동의 상자는 `.upload__consent` 재사용 |

### `inputStyle` 을 지웠다

인라인 스타일 객체를 여섯 화면이 퍼뜨리고 있었다. `.input` 클래스가 같은 일을 하고
**포커스 링과 오류 배경까지 한다** — 인라인 객체로는 `:focus` 를 쓸 수 없어서
시안이 그린 `box-shadow: 0 0 0 3px primary-100` 이 통째로 빠져 있었다.

### 예외를 없애는 게 목적이 아니다

랜딩 h1 은 여전히 52px 이고 스케일에 없다. **시안이 그렇게 그렸기 때문이다.**
검사기가 막는 건 "화면 파일에 숫자를 적는 것"이고, 화면 전용 클래스로 `components.css`
에 모으면 통과한다. 목적은 예외를 없애는 게 아니라 **예외가 한 곳에 모여 눈에 보이게**
하는 것이다.

**이 화면이 없어서 신규 시공자는 등록을 끝낼 수 없었다.** 연쇄가 이랬다 —
활동명을 채울 화면이 없으니 `businessName` 이 빈 채로 남고, `/pros` 의 공개 조건

경로는 `/pro/profile` 이다. **내가 고른 게 아니라 서버가 이미 약속한 주소다** —
`POST /me/profile` 이 PRO 에게 `next: '/pro/profile'` 을 돌려주고 있었다.

`profile_completeness` 컬럼은 처음부터 있었는데 **아무도 쓰지 않아 항상 0이었다.**

`user/index.ts` 가 "아직 여기 없는 것"으로 적어둔 파일이 바로 이거였다.

필수는 셋(활동명·공종·지역)이고 나머지 둘(소개·사업자등록번호)은 권장이다.

## C-03 의뢰 상세(내 것) — 고객이 제안을 비교할 수 있게 됐다

**이 화면이 없어서 두 가지가 막혀 있었다.** 고객은 받은 제안을 `/contacts` 의 평평한
목록으로만 봤고(어느 의뢰에 온 제안인지 묶이지 않는다), **자기 의뢰를 마감할 방법이
아예 없었다** — `POST /reference-requests/:id/close` 는 있는데 부르는 화면이 없었다.

그리고 `/requests/mine` 은 **어디로도 이어지지 않는 목록**이었다. 카드에 링크가 없었다.
카드 전체를 상세로 가는 링크로 만들었다.

### `GET /reference-requests/:id/proposals` 를 새로 만들었다

`GET /contacts` 로 대신할 수 없었다. 그건 "내 컨택 전부"를 상대 요약과 함께 주는데,
C-03 은 **한 의뢰 안에서 제안을 서로 비교하는 화면**이라 시공자의 승인 여부·경력·
활동 지역·사례 사진 3장까지 한 응답에 있어야 한다. 목록을 보고 프로필로 나갔다
돌아오게 만들면 비교가 끊긴다.

- 소유자 전용. 남의 의뢰에 누가 제안했는지는 **존재 자체가 비밀이라 404** 다
- **시공자는 403.** 경쟁 제안을 보게 된다
- 커서 페이지네이션. 사례 사진은 `IN` 한 번으로 묶어 가져온다 — 제안마다 조회하면
  20건에 21쿼리다
- **`phone` 을 SELECT 하지 않는다.** 수락 후에도 이 목록은 변하지 않는다.
  연락처 공개는 컨택 상세(M-02)가 전이를 확인한 뒤에 하는 일이다

식별자는 `userId` 다. C-06 에서 `userProfileId` 로 냈다가 링크가 404 났던 전례가 있어
e2e 로 못 박았다.

### 마감·다시 열기

마감은 기존 API 를 부른다. **다시 열기는 별도 API 가 아니라 `publish` 를 다시 부른다** —
`publish` 는 이미 PUBLISHED 일 때만 거부하므로 CLOSED 를 되살릴 수 있고, 그 과정에서
필수 항목을 재검증한다.

재검증이 실패할 수 있다. 사진을 지운 뒤 다시 열려고 하면 400 이다. 브라우저에서 그
400 을 실제로 받았는데 **서버 메시지("필수 항목이 비어 있습니다")만으로는 무엇을
고쳐야 할지 알 수 없었다.** `details.missing` 을 사람 말로 바꿔 보여준다.

1. **`되돌리기` 를 누르면 토스트가 "1명 반려했습니다"라고 했다.** 되돌리기는 실제로

2. **로드 실패가 "0건"으로 보였다.** `queue` 가 null 일 때도 표를 그려서 머리글만

3. **`process.env` 를 시드 스크립트에서 읽었다.** `pnpm qc` 가 잡았다 —
   규칙에 예외를 내는 대신 인자 하나로 통로를 줄였다.

첫 조치로 이미 처리됐다는 걸 알 수 있어 중복 조치를 막는다. 대상 이름·상태를

## G-01 이용 방법 — 화면을 만들지 않고 섹션으로 끝냈다

[[열린 질문]] Q8 의 답이다. 랜딩의 `3단계로 끝납니다` 에 `id="how"` 를 주고 헤더·푸터의
`이용 방법` 을 그 앵커로 연결했다. **화면 목록은 21개 그대로다.**

섹션이 이미 같은 일을 하고 있었다는 게 근거다. 화면을 새로 만들면 같은 설명이 두 곳에
생기고 **둘 중 하나는 반드시 낡는다.**

`고객으로 / 시공자로` 토글로 3단계·FAQ 3개·CTA 두 개가 함께 바뀐다. 토글 때문에
클라이언트 컴포넌트로 떼어냈다 — 랜딩의 나머지는 SSR 로 남아 색인된다.

### 지킬 수 없는 약속 넷을 고쳤다

시안 카피를 그대로 옮기려다 확인해보니 넷이 사실이 아니었다.
**랜딩은 서비스가 처음 하는 말이다. 여기서 못 지킬 말을 하면 나머지가 다 의심받는다.**

| 시안 카피 | 무엇이 틀렸나 | 고친 것 |
| --- | --- | --- |
| "사업자등록증과 자격 서류를 올리면 **영업일 1~2일 내** 확인됩니다" | 서류 업로드가 없고 심사 기한을 정한 곳도 없다 | "사업자등록번호를 넣으면 승인 대기로 들어갑니다" |
| "**응답 속도와 수락률이 목록 노출에 반영**됩니다" | `/pros` 정렬은 등록순이다. 그런 가중치는 없다 | 그 문장을 지웠다 |
| "**공종별로 의뢰를 나눠** 올리면 됩니다" | 한 의뢰에 공종을 여러 개 담을 수 있다(`workCategoryCodes` 는 배열) | "의뢰 하나에 공종을 여러 개 고를 수 있습니다" |
| "한 의뢰에 같은 시공자가 두 번 제안할 수 없습니다" | **내가 쓴 문장이고, 그것도 틀렸다.** 부분 유니크 인덱스가 막는 건 `(requester, receiver) WHERE status='REQUESTED'` 다 — 의뢰 단위가 아니라 **상대 단위**다 | "같은 고객에게 답을 기다리는 제안이 있으면 새로 보낼 수 없습니다" |

마지막 줄이 중요하다. 시안을 고치면서 **내가 새 거짓말을 하나 심었고** 인덱스 정의를
직접 열어보고서야 잡았다. 카피에 규칙을 적을 땐 그 규칙의 정의를 봐야 한다.

### 검증

`/#how` 로 들어가면 섹션 상단이 88px 에 앉는다(헤더 하단 69px) — 제목이 가리지 않는다.
모바일은 `scroll-margin-top` 을 64px 로 낮췄고(헤더 56px) 역시 안 가린다.
토글은 제목·부제·3단계·FAQ·CTA 다섯 묶음을 한 번에 바꾼다.
