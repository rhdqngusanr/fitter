## 지금 막혀 있는 것

**공개 URL 전에 남은 것 하나 — rate limit 이 없다.** [[API 명세]]가 가입·로그인·신고에
한도를 요구했는데 `apps/api` 에 throttle 코드가 한 줄도 없다. 로컬에서는 무해하지만
**주소가 밖에 나가면 열린 문**이다. 특히 신고는 비로그인도 낼 수 있고 인정되면 대상이
즉시 비공개가 된다. → [[배포 준비 상태]]

**키 교체.** 배포 과정에서 `JWT_SECRET` 과 R2 키가 대화에 노출됐다. 각각 1분이면
바꾼다. 친구 테스트용 환경이라 당장 위험하진 않지만 **주소를 더 넓게 뿌리기 전에** 한다.

개발은 막히지 않는다. **2026-07-25 Docker Desktop이 설치되어 DB 차단이 풀렸다.**

`docker compose up -d`로 PostgreSQL 16과 Redis 7이 뜨고, 마이그레이션 실행·롤백·재적용이 전부 검증됐다. Redis는 P4-2 BullMQ에서 쓴다.

**DB 제약이 실제로 [[확장 규약]]을 강제하는 것도 확인했다.** 24평이 79.34㎡로 자동 계산되고, 0평·출처 없는 외부 사진·자기 자신에게 보내는 컨택·중복 컨택이 전부 거부된다. 애플리케이션이 실수해도 DB가 막는다.

남은 미결정 중 구현을 막는 것 하나.
- **Q4 컨택 만료 판정** — P4-6 전에 정해야 한다 (Q7은 ADR-010에서 해결)

## Phase 0~2에서 실제로 얻은 것

세 가지가 이 구간의 성과다. 나머지는 그 셋을 떠받치는 작업이었다.

**첫째, 시안이 데이터를 잘못 받고 있다는 걸 코드 작성 전에 잡았다.** [[시안 검수 결과]]가 [[확장 규약]] 위반 4건을 찾았다 — 평수·지역이 자유 텍스트, 사진 출처 필드 부재, 공종 목록 5갈래 분열. 시안은 그림이 아니라 폼의 명세이므로 그대로 구현했으면 2차에서 스키마를 갈아엎어야 했다.

**둘째, 기간 가정이 틀렸다는 걸 착수 전에 확인했다.** Must 30개가 413시간으로 추정돼 4~6주 가정의 2.3~3.4배였다. 범위를 24개로 줄이고 기간을 8~10주로 고쳤다. 이걸 모르고 시작했으면 [[리스크 레지스터]]의 "범위 폭발"이 그대로 현실이 됐을 것이다.

**셋째, 원칙이 문서가 아니라 강제 장치가 됐다.** [[구조적 원칙]] 1조는 이제 지켜야 할 규칙이 아니라 어길 수 없는 제약이다. 도메인에 프레임워크를 import 하면 패키지 경계가 막고 ESLint가 근거 노트를 가리킨다. 공종·용량 상수도 `packages/shared` 한 곳에 있어 화면이 제멋대로 들고 있을 수 없다.

## 최근 결정 (2026-07-26)

- **⚠️ Phase 4 화면을 만들면서 `design/`의 시안을 열지 않았다.** 디자인 시스템에서 컬러 토큰만 grep으로 뽑아 쓰고 레이아웃·컴포넌트·상태는 즉흥으로 만들었다. 사용자가 지적해서 알았다. 차이는 [[시안 대조 결과]]에 항목별로 적었다 — 갤러리에 지역 필터가 통째로 빠졌고, 상세에 "연락처는 수락 후 공개" 안내가 없다.
- **원인은 [[세션 부팅 프로토콜]]에 있었다.** "디자인·화면 작업이면 [[화면 목록]], [[디자인 원칙]]을 읽어라"고만 되어 있고 **시안 파일을 열라는 지시가 없었다.** 노트는 "왜"를 담고 시안은 "무엇을"을 담는데, 노트만 읽으면 색만 맞고 구조는 새로 지어진다. 화면↔시안 매핑 표를 프로토콜과 `CLAUDE.md` 양쪽에 박았다.
- **토큰 정본은 시안이고 `tokens.css` 는 사본이다.** 사본이 정본을 앞질러 이름을 바꾸고 있었다 — `--shadow-1/2/3` → `--shadow-sm/md`, `--color-border-focus` → `--color-focus-ring`. **다크 모드 토큰 한 벌은 통째로 빠져 있었다.** 지금 안 쓴다고 뺐다면 나중에 켜려 할 때 이미 못 켠다. 전부 시안대로 되돌렸다.
- **`pnpm qc`에 토큰 대조 검사를 넣었다. 문서로만 두면 또 어긴다.** 시안 HTML과 `tokens.css`의 **이름 집합**을 비교해서 한쪽에만 있으면 error다. **값이 아니라 이름만 본다** — 값은 근거가 있으면 바꿀 수 있지만(포커스 색이 그랬다) 이름을 바꾸는 건 근거가 있을 수 없다. 일부러 깨뜨려서 3건을 잡는 걸 확인했다.
- **Pretendard를 실제로 로드하기 시작했다.** 토큰에 이름만 적어놓고 CDN을 안 걸어서 그동안 시스템 폰트로 그려지고 있었다. 자간과 숫자 폭이 달라 시안과 대조가 애초에 안 맞았다. `font-feature-settings:"tnum"`도 같이 넣었다 — 금액·평수가 세로로 늘어서는 화면이라 시안이 요구한 설정이다.

- **P4-8 완료. 테스트 168개. 쓰는 동안 결함을 하나 더 잡았다 — 커버 사진을 바꾸면 500이 났다.** 커버는 하나만 존재할 수 있고 DB 부분 유니크 인덱스가 그걸 강제하는데, 새 커버를 넣기 전에 기존 걸 내리지 않았다. 사용자에게는 "이걸 대표 사진으로"라는 정당한 요청인데 서버가 터진 것처럼 보인다. **의뢰 사진에도 같은 결함이 있어 같이 고쳤다** — 한쪽에서 발견한 건 다른 쪽도 봐야 한다. 내리기와 넣기를 한 트랜잭션으로 묶은 이유는, 내리기만 성공하면 커버가 하나도 없는 항목이 남기 때문이다.
- **역할이 토큰 안에 있다는 사실을 테스트로 고정했다.** 이걸 안 적어두면 다음 사람은 "가드가 DB를 읽게 하면 되잖아"로 고치려 든다. 그러면 **모든 요청에 조회가 하나 붙는다.** 무상태를 택한 대가를 클라이언트가 치르기로 한 결정이고, 그 근거가 코드 옆에 남아 있어야 되돌릴지 말지 판단할 수 있다.
- **테스트가 문서보다 오래간다는 걸 이번에 체감했다.** 이번 세 건(역할-토큰, 지역 코드 5자리, 커버 단일성)은 전부 "화면이 기대는 서버 계약"이다. 서버만 보면 바꿔도 될 것 같지만 바꾸면 화면이 조용히 깨진다.

- **⚠️ 신규 가입자를 전부 막고 있던 버그를 잡았다. 역할을 골라도 토큰이 안 바뀌었다.** 역할은 액세스 토큰 안에 박혀 있는데 가입 시점에는 아직 없어서 `null` 이다. 역할 선택 후 옛 토큰을 계속 쓰면 **역할 가드가 걸린 모든 API가 403** 이 된다 — 방금 시공자를 선택한 사람이 포트폴리오를 못 올린다. 역할 선택 직후 리프레시로 토큰을 다시 받게 고쳤다. **화면을 실제로 눌러보지 않았으면 못 찾았을 종류다** — 타입도 테스트도 통과한다.
- **P4-2 이미지 파이프라인 완료. 업로더 하나가 두 용도를 겸한다.** 다만 **사진마다 묻는 게 다르다** — 의뢰는 출처(내 사진/남의 사진 + 원본 주소), 포트폴리오는 단계(시공 전/후/작업 중)다. 포트폴리오는 시공자 본인 작업물이라 출처를 물을 이유가 없고, before/after 대비가 실력을 가장 잘 보여준다.
- **P-02 등록 화면은 공개 조건이 두 개라는 걸 올리기 전에 말한다.** 항목을 공개해도 승인 전에는 갤러리에 안 뜬다. 이걸 안 알려주면 시공자는 올리고 나서 "안 보이는데?" 하고 떠난다. `내 사례` 화면 상단에도 승인 대기 배너를 띄우고, 개별 항목에도 `공개 중 · 승인 대기`로 표시한다.
- **비용 공개 체크를 풀면 금액 칸이 사라진다.** 안 쓸 값을 화면에 남겨두지 않는다. 서버도 "비공개인데 금액 있음" 조합을 거부하므로 화면과 서버가 같은 말을 한다.
- **커버는 AFTER 중 첫 장이다.** 목록에서 보고 싶은 건 결과지 철거 직전 모습이 아니다. 사용자가 고르게 하지 않고 단계에서 유도한다.

- **컨택 화면(M-01/M-02) 완료. 서비스가 끝까지 돈다.** 갤러리에서 사진을 보고 → 문의를 보내고 → 상대가 수락하면 연락처가 열린다. 이 셋이 이어지는 게 [[서비스 정의]]가 말한 전부다.
- **목록에서는 상태를 바꿀 수 없다. 전이는 상세에서만 일어난다.** 목록에 수락 버튼을 달면 상대 메시지를 읽지 않고 누르게 된다. **수락은 되돌릴 수 없다** — 연락처가 이미 넘어갔기 때문이다.
- **화면은 연락처 공개 여부를 판단하지 않는다.** `phone` 키가 응답에 있는지 없는지만 본다. 판단이 서버와 화면 두 곳에 있으면 언젠가 갈라지고, 갈라지는 순간 새는 쪽이 이긴다. 마스킹된 값을 받아 화면이 가리는 구조였다면 이 보장이 없다.
- **버튼을 감추는 건 보안이 아니라 친절이다.** 수락은 받은 사람에게만, 취소는 보낸 사람에게만 보인다. 그래도 최종 판단은 서버가 한다 — 보낸 사람이 수락을 시도하면 **409**로 막히는 걸 확인했다.
- **문의 방향은 사용자에게 고르게 하지 않는다.** 포트폴리오에서 왔으면 `CUSTOMER_TO_PRO`, 의뢰에서 왔으면 `PRO_TO_REQUEST`다. 어디서 왔는지로 정해지는 걸 물어보면 틀릴 기회만 준다.
- **갤러리 상세의 문의 버튼은 로그인 여부를 따지지 않고 그냥 문의 화면으로 보낸다.** 갤러리는 SSR이라 서버가 로그인 여부를 모른다(액세스 토큰이 브라우저 메모리에만 있으므로). 판단을 클라이언트 화면 한 곳에 몰아두면 SSR 화면이 세션을 흉내 낼 필요가 없다.
- **제안 금액은 목록에도 띄우되 없으면 아예 안 쓴다.** "미정"이라고 쓰면 안 적은 게 흠처럼 보인다. 금액을 안 밝힌 걸 강조하지 않는 건 [[ADR-010 - 가격 정책 모델]]의 유인 구조와 같은 원칙이다.

- **의뢰 등록(C-01) 완료. [[확장 규약]]을 화면이 강제한다.** 평수는 `type=number`, 지역은 시도→시군구 2단계 셀렉트, 공종은 [[도메인 용어집]] 코드 칩, 나머지는 enum 셀렉트다. **자유 텍스트를 받는 칸이 하나도 없다** — 주소 원문 칸도 "24평쯤" 칸도 만들지 않았다. 화면에 칸이 있으면 언젠가 들어온다.
- **사진 출처는 사진마다 받는다. 의뢰 단위가 아니다.** 한 의뢰 안에서도 "내가 찍은 것"과 "인터넷에서 본 것"이 섞인다. 의뢰 단위로 한 번 물으면 그 구분이 사라지고, 신고가 들어왔을 때 어느 사진이 문제인지 특정할 수 없다. 기본값은 **EXTERNAL**이다 — 잘못 신고되는 쪽이 훨씬 비싸다.
- **화면에 들어오는 순간 DRAFT를 만든다.** 사진은 의뢰에 매달리므로 의뢰 행이 먼저 있어야 업로드할 수 있다. 중간에 나가면 고아 파일은 정리 배치가 치운다 — 그 배치를 P4-2에서 미리 만들어둔 게 여기서 값을 했다.
- **지역 조회 API를 새로 만들었다(`GET /regions`). 공종과 다르게 다뤘다.** 공종은 13개 고정이라 `packages/shared` 정본을 화면이 그대로 쓰지만, 지역은 전국으로 늘면 250개가 넘는다. 그걸 클라이언트 번들에 넣을 이유가 없다. **정본은 둘 다 DB이고, 다른 건 전달 방식뿐이다.**
- **평↔㎡ 상수를 `packages/shared` 로 옮겼다.** 화면이 입력 중에 ㎡를 같이 보여줘야 하는데 웹은 domain 을 import 할 수 없다(의존 방향은 항상 안쪽이다). 화면에서 3.3058 을 다시 적으면 정본이 갈라지므로 **숫자만** 바깥으로 빼고 변환·검증 규칙은 domain 에 남겼다. 도메인 62개 테스트 그대로 통과했다.
- **QC가 또 잡았다. 이번엔 안내 문구였다.** "한 장당 10MB까지입니다"라고 적었는데 한도가 바뀌면 문구가 거짓말이 된다. `MAX_IMAGE_BYTES` 에서 계산하게 고쳤다. **사람이 읽는 문장도 정본에서 나와야 한다**는 걸 이번에 배웠다.

- **인증 UI 완료. [[ADR-002 - 인증과 권한 모델]]이 정한 걸 그대로 구현했고, 지켜졌는지 브라우저에서 확인했다.** 액세스 토큰은 React ref에만 있고 `localStorage`·`sessionStorage`·DOM 어디에도 없다. 새로고침하면 httpOnly 쿠키로 `/auth/refresh` 를 한 번 불러 복원한다. 로그아웃하면 쿠키가 죽어서 재발급이 401이 된다. **이건 코드를 읽어서가 아니라 실제로 브라우저 저장소를 뒤져서 확인했다** — "메모리에만 둔다"는 주장은 그렇게밖에 검증이 안 된다.
- **로그인이 필요한 화면은 SSR을 포기한다.** 토큰이 브라우저 메모리에만 사니 서버는 그 사용자가 누군지 알 방법이 없다. `(app)` 그룹이 이미 noindex라 잃는 것도 없다. 보안을 위해 SEO를 버린 게 아니라, 애초에 색인되면 안 되는 화면들이다.
- **액세스 토큰 만료는 사용자에게 보이지 않게 처리한다.** 15분이라 쓰는 도중에 만료되는 게 정상이다. 401이 오면 조용히 갱신하고 **한 번만** 재시도한다. 무한 재시도는 서버를 때리고, 재시도가 없으면 멀쩡한 사용자가 15분마다 튕긴다.
- **역할 선택은 가입과 분리했다.** 가입 폼에서 역할까지 고르게 하면 "일단 둘러보려던" 사람을 거기서 잃는다. 대신 온보딩 화면에서 **승인 게이트를 미리 알린다** — 시공자를 고르면 포트폴리오 공개에 승인이 필요하다는 걸 그 자리에서 말한다. 나중에 알면 속았다고 느낀다.
- **로그인 실패는 이메일과 비밀번호를 구분해 알려주지 않는다.** 구분하면 "이 이메일이 가입돼 있는가"를 확인해주는 조회 도구가 된다.
- **`next` 파라미터는 내부 경로만 받는다.** `//evil.com` 을 브라우저는 외부 주소로 읽으므로 슬래시 하나로 시작하는 것만 통과시킨다. 열린 리다이렉트는 로그인 화면에서 제일 흔하게 나오는 구멍이다.

- **상세(C-05) 완료. 공개 동선이 랜딩 → 갤러리 → 상세 → 문의까지 끊기지 않고 이어진다.** 상세는 컨택 직전 화면이라 신뢰 판단이 여기서 끝나야 한다 — 그래서 **API 상세 응답에 시공자 정보가 아예 없던 걸 채웠다**(소개글·경력·활동 지역). 카드보다 근거를 더 준다. 동시에 `phone` 키가 응답 어디에도 없다는 걸 테스트로 고정했다. 신뢰 근거를 늘리는 요구와 연락처를 막는 요구가 충돌하는 유일한 지점이다.
- **비공개 비용은 화면에서도 문구조차 띄우지 않는다.** 응답에 키 자체가 없으니 "비공개"라고 표시할 근거도 없다. 안 밝힌 걸 강조하면 [[ADR-010 - 가격 정책 모델]]의 유인 구조가 뒤집힌다 — 공개가 이득이어야지 비공개가 낙인이 되면 안 된다.
- **㎡는 화면이 계산하지 않는다.** 서버가 평에서 파생한 `areaM2` 를 그대로 쓴다. 생성 컬럼을 버릴 때 정한 원칙("파생 경로는 하나여야 한다")이 화면까지 적용된다.
- **상세도 1200px 파생만 쓴다. 원본은 어떤 화면에도 오지 않는다.** 무단 재사용을 조금이라도 어렵게 만드는 게 저작권 리스크 대응의 일부다.
- **없는 항목·비공개 항목·미승인 시공자의 항목이 전부 같은 404다.** 화면도 셋을 구분하지 않는다 — 구분해 알려주면 "존재는 한다"가 샌다.
- **첫 화면이 실제로 돈다. 갤러리(C-04) SSR 완료.** [[시안 검수 결과]] 6·7번이 지적한 빈 상태 2갈래가 화면에서 실제로 갈라진다 — 콘텐츠가 0건이면 히어로 카피까지 "첫 시공 사례를 기다립니다"로 바뀌고, 필터 때문에 0건이면 "필터 초기화"를 준다. 필터 상태는 URL에 살아서 공유·북마크·뒤로가기가 그냥 동작한다.
- **연락처 인터셉터가 Prisma `Decimal`을 부수고 있었다. 타입은 이걸 못 잡는다.** 인터셉터가 `Object.entries`로 응답을 재조립하면서 프로토타입을 벗겨내 평수가 `{"s":1,"e":1,"d":[24]}`로 나갔고 화면에는 `NaN평`이 찍혔다. 이제 `toJSON`을 가진 객체는 자기 직렬화에 맡기고 **그 결과를 다시 sanitize에 통과시킨다** — 성능 때문에 프라이버시를 뚫지 않는다. e2e로 고정했다. **교훈: 전역 인터셉터는 자기가 모르는 타입을 지나가게 해야지 재조립하면 안 된다.**
- **이미지는 서명 URL이 아니라 공개 버킷 + 키 조합으로 띄운다.** 목록에서 썸네일 N장마다 서명을 발급하면 요청이 N배가 된다. 개발은 MinIO 익명 download, 운영은 R2 공개 도메인이고 바뀌는 건 `NEXT_PUBLIC_IMAGE_BASE_URL` 하나다. 원본이 아니라 **400px 파생만** 이 경로로 나간다.
- **`process.env` 진입점은 "파일 하나"가 아니라 "앱마다 하나"다.** Next는 `process.env.NEXT_PUBLIC_X`를 **빌드 시점에 문자열로 치환**하므로 다른 패키지의 함수로 감싸면 클라이언트 번들에서 값이 사라진다. `apps/web/src/lib/env.ts`를 두 번째 진입점으로 인정하고 QC 규칙을 그렇게 고쳤다. `packages/*`는 여전히 자격이 없다 — 어느 앱에 실릴지 모르기 때문이다.
- **P5-1 데모 시드 완료 (`db:seed:demo`).** 승인 시공자 3명·포트폴리오 6건. **"테스트1, 테스트2"를 쓰지 않았다** — 빈 갤러리에 처음 들어온 사람이 보는 화면이 서비스의 첫인상이고 그게 [[리스크 - 콜드스타트]]의 핵심이다. 사진은 색면 이미지를 생성해 올린다. 목적은 예쁜 화면이 아니라 원본→썸네일 파생→공개 URL 경로가 실제로 이어지는지 보는 것이다. 데모 계정의 `passwordHash`는 `null`이다 — 로그인 가능한 데모 계정은 뒷문이다.
- **포커스 링을 primary와 분리했다.** 시안은 `--color-border-focus`가 `--color-primary-500`과 같은 값이라 primary 버튼 위에서 포커스 링이 보이지 않았다([[시안 검수 결과]] 8번). 토큰 단계에서 `--color-focus-ring`을 secondary 계열로 갈랐다.

- **P4-6 컨택 상태머신 완료. 기술 하이라이트 둘이 모두 섰다.** 전이는 도메인 순수 함수 하나만 거치고 상태를 직접 UPDATE하는 코드는 없다. 주체 검증(수락은 수신자만·취소는 요청자만)까지 포함해 도메인에서 24케이스를 검증했다.
- **연락처 차단은 응답 직렬화 인터셉터가 한다. 기본값이 "제거"다.** 어떤 경로로 들어온 `phone` 키든 지우고, 서비스가 `__revealedPhone`으로 명시한 것만 되살린다. Prisma `include`로 유저 행을 통째로 실어도 새지 않는다 — [[ADR-002 - 인증과 권한 모델]] 결정 6이 지목한 가장 현실적인 사고 시나리오가 이것이었다.
- **[[열린 질문]] Q4 해결: 만료는 배치.** 조회 시점 판정은 아무도 조회하지 않으면 알림이 영영 안 간다. 배치도 전이 함수를 거쳐 우회 경로를 만들지 않았다.
- **제3자의 전이 시도는 409가 아니라 404다.** 도메인은 409(불가능한 전이)를 던지지만 전송 계층에서 404로 바꾼다 — 409는 "그 컨택이 존재하고 지금 이런 상태다"를 알려준다.
- **P4-5 탐색 API 완료. 빈 상태를 두 갈래로 나누는 신호를 API가 준다** — `hasAnyContent`. "필터 때문에 0건"과 "서비스에 아직 아무것도 없어서 0건"은 완전히 다른 화면인데 [[시안 검수 결과]] 6·7번이 지적한 대로 시안에서 섞여 있었다. 결과가 비었을 때만 한 번 더 조회하므로 평상시 비용은 0이다.
- **복수 선택 필터는 OR다.** AND면 콘텐츠가 적은 초기에 거의 항상 0건이 된다.
- **P4-4 포트폴리오 API 완료. 공개 조건 두 개가 실제로 강제된다.** 승인을 철회하면 항목의 `status`가 여전히 `PUBLISHED`인데도 갤러리에서 즉시 사라지고 비로그인 상세도 404가 된다(소유자는 계속 볼 수 있다). [[엔티티 - PortfolioItem]]이 "빠뜨리기 쉽다"고 경고한 지점을 테스트로 고정했다.
- **비공개 비용은 응답에서 키 자체를 뺀다.** `null`을 넣으면 "금액이 없다"와 "안 밝히기로 했다"가 섞인다. 연락처와 같은 원칙이다.
- **P4-3 의뢰 등록 API 완료.** DRAFT 부분 저장 → 공개 시 완성 판정. **`areaPyeong`·`regionCode`·`housingType`을 nullable로 바꿨다** — DRAFT는 본질적으로 미완성인데 NOT NULL이면 임시값을 넣어야 하고, 그러면 "24평이라고 답했다"와 "아직 안 물어봤다"를 구분할 수 없다. 그 구분이 사라지면 2차 가격 통계가 오염된다.
- **평수 상한을 1000 → 500으로 좁혔다.** [[P4 - 기능 구현]] P4-3이 명시한 값이고, 반셀프 인테리어에서 500평 넘는 의뢰는 사실상 없다. 상한이 낮을수록 오타(240 → 2400)를 더 잘 잡는다.
- **P4-2 서버 이미지 파이프라인 완료.** 서명 URL 직접 업로드(파일이 서버를 경유하지 않는다), **매직 넘버로 확장자 위조 차단**, 400/1200 webp 썸네일 파생(BullMQ), EXIF 제거(sharp가 메타데이터를 안 싣는 것이 곧 제거다), 고아 파일 10분 주기 정리. 스토리지는 MinIO(개발)/R2(운영) — S3 API라 어댑터가 같다.
- **고아 파일은 `upload_intents` 방식으로 잡는다.** 서명 URL 발급 시 의도를 남기고 등록되면 소비 처리, 1시간 미소비면 정리. 버킷 전체를 리스팅하는 방식보다 싸고, **발급받은 사람만 등록할 수 있다**는 보안 성질이 덤으로 붙는다 — 이게 없으면 남이 올린 키를 자기 의뢰에 붙일 수 있다.
- **P4-1 인증 완료.** JWT(액세스 15분) + 리프레시 회전·재사용 탐지, `httpOnly` 쿠키. **전역 가드 기본값이 "인증 필수"**이고 `@Public()`만 뚫는다. 비밀번호는 Node 내장 scrypt를 썼다 — argon2는 네이티브 모듈이라 이 PC의 Application Control 정책에 막힌다. 계정 열거를 막으려 "없는 이메일"과 "틀린 비밀번호"를 같은 응답으로 통일했고 더미 해시로 응답 시간까지 맞췄다.
- **`area_m2` 생성 컬럼을 되돌렸다.** Prisma가 `GENERATED ALWAYS`를 표현하지 못해 스키마와 DB가 영구히 어긋난 것으로 보이고, `migrate dev`가 매번 실패한다. 남은 모든 마이그레이션에 걸리는 세금이라 걷어냈다. ㎡ 파생은 도메인의 `pyeongToSquareMeters` 하나로 통일했다 — **파생 경로는 하나여야 한다.** [[확장 규약]] 1조의 진짜 방어선(`DECIMAL` + 범위 CHECK)은 그대로다.
- **가격 전략 확정 (ADR-010).** 잠정안 B→D→A를 검토해 **B→B⁺→D→A(표시형)**으로 고쳤다. 급소는 D의 데이터가 안 쌓인다는 것이었다 — 실거래가는 시공자 자발 공개에만 의존하는데 거래가 플랫폼 밖에서 일어나기 때문이다. 해법은 **컨택에 제안 금액을 받는 것**이고, 제안은 플랫폼 안에서 일어나므로 이탈과 무관하게 쌓인다. 그리고 **A는 강제가 아니라 표시형**으로 바꿨다 — 범위를 강제하면 재판매가격유지 소지가 생기고 정직한 예외를 쫓아낸다.
- **P2-3 완료. `CLAUDE.md`가 색인 역할을 유지한 채 139줄이 됐다**(상한 200). 폴더별 책임, 새 기능 추가 순서(안에서 바깥으로), 네이밍 표, 금지 목록 11개, 커밋 컨벤션. 상세는 전부 brain 링크로 넘겼다.
- **P2-2 스캐폴딩 완료.** pnpm 모노레포(`apps/api` · `apps/web` · `packages/domain` · `packages/shared`). 도메인 순수성은 패키지 경계 + ESLint `no-restricted-imports`로 **실제로 강제된다**(도메인에 `@nestjs/common`을 넣으면 근거 노트를 가리키며 에러). 공종 13종과 이미지 10MB를 `packages/shared`에 정본으로 두어 시안의 분열을 코드 차원에서 해소했다.
- **테스트 러너는 ts-jest.** 이 PC의 Windows Application Control 정책이 서명 없는 네이티브 모듈(`@swc/core`)을 차단해서 vitest+SWC를 못 쓴다. 보안 정책을 끄지 않고 우회했고, 부수 효과로 빌드와 테스트가 같은 컴파일러(tsc)를 쓰게 됐다. **Next.js·esbuild는 정상**이라 다른 곳엔 영향 없다.
- **산출물은 `brain/70-산출물/`에 둔다.** `docs/`가 GitHub Pages로 공개되기 때문에 PRD·유저 스토리·백로그를 옮기고 ADR은 `50-결정/`으로 보냈다. [[노트 작성 규칙]]에 "산출물은 파생물이고 원 노트가 이긴다" 조항을 추가했다. `docs/`에는 목업 HTML만 남는다.
- **P2-2 폴더 트리 승인됨.** `packages/domain` 분리형 pnpm workspace 모노레포.
- **P1-3 범위 확정. 기간 가정을 4~6주 → 8~10주로 수정했다.** Must 30개가 413시간으로 추정돼 기존 가정의 2.3~3.4배였다. Must를 24개(약 314시간)로 줄였고, 이미지 파이프라인과 컨택 상태머신은 자르지 않았다. 근거는 `brain/70-산출물/백로그.md`.
- P1-2 유저 스토리 완료 → `brain/70-산출물/유저 스토리.md`. **공종 정본은 [[엔티티 - WorkCategory]]의 시드 13종**으로 확정(시안에서 5갈래로 갈라져 있던 것을 해소). 컨택 만료 판정 방식은 여전히 미결이지만 수용 기준은 방식과 무관하게 동일하도록 썼다.
- P1-1 PRD 완료 → `brain/70-산출물/PRD.md`. 시안에서 갈라져 있던 이미지 용량을 **장당 10MB로 통일**(정본), 성능 목표(p95 300ms · LCP 2.5초 · 동시 50명)는 근거 없는 값이라 `가정:`으로 명시하고 실측 후 갱신하기로 했다.
- P0-4 시안 검수 완료 → [[시안 검수 결과]]. 시안 HTML은 지금 고치지 않고 판단만 노트에 남긴다. 실제 수정은 코드에서 한 번만 한다.
- 친구들과의 시안·기획 합의는 **보류**. 이대로 진행하고 나중에 공유한다.
- 기술 스택 **B(Next.js + NestJS + PostgreSQL + S3호환)** 확정. 근거 ADR-001. 방향 스타트업·스케일업, 풀 TypeScript.
