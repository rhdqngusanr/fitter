## ⚠️ 공개 URL 이 되기 전에 반드시 할 것 — 둘

### 리프레시 쿠키가 크로스사이트에서 죽는다 (2026-07-26 발견)

`auth.controller.ts` 의 쿠키가 `sameSite: 'lax'` 다. 웹을 `*.vercel.app`, api 를
`*.railway.app` 에 올리면 **다른 사이트**라 브라우저가 Lax 쿠키를 크로스사이트 fetch
응답에서 저장조차 하지 않는다.

증상이 고약하다 — **로그인은 성공하고 화면도 돈다.** 액세스 토큰은 본문으로 오기
때문이다. 그런데 새로고침할 때마다 로그아웃된다. [[ADR-002 - 인증과 권한 모델]]이
설계한 "메모리 토큰 + 쿠키 복원"이 통째로 무너지는데 로그에는 401 말고 아무것도 안 남는다.

| 해법 | 대가 |
| --- | --- |
| **도메인 하나로 묶기** (`fitter.x` / `api.fitter.x`) | 도메인 값. **코드 변경 없음** |
| `sameSite: 'none'` | 무료지만 사파리·아이폰이 서드파티 쿠키를 막아 같은 증상이 남는다 |

**사용자가 도메인 구매를 택했다(2026-07-26).** 따라서 코드는 그대로 두고 배포를
같은 등록 도메인 아래로 묶는다. 이걸 어기고 플랫폼 서브도메인으로 올리면 되살아난다.

### Rate limit 이 구현돼 있지 않다

[[API 명세]]가 직접 요구한 것이다.

| 대상 | 명세가 정한 한도 | 왜 |
| --- | --- | --- |
| `POST /auth/signup` | IP 10회/시간 | 계정 대량 생성, 이메일 존재 여부 탐색 |
| `POST /auth/login` | 계정 5회/10분 · IP 20회/10분 | 크리덴셜 스터핑 |
| `POST /reports` | 계정·IP 10건/시간 | **신고 폭탄으로 콘텐츠를 내릴 수 있다** |

`apps/api` 에 throttle 관련 코드가 한 줄도 없다. 로컬에서는 무해하지만 **주소가 밖에
나가는 순간 열린 문**이다. 특히 신고는 [[리스크 - 레퍼런스 사진 저작권]] 때문에
**비로그인도 낼 수 있게 열어뒀다** — 인정되면 대상이 즉시 비공개가 된다.

NestJS 는 `@nestjs/throttler` 로 반나절이면 된다. **이것만 하고 배포해도 된다.**

## 사용자가 정해야 하는 것

내가 정할 수 없다. 계정·비용·도메인이 걸린다.

### 어디에 올리나

| 조각 | 필요한 것 | 비고 |
| --- | --- | --- |
| web | Next.js 호스팅 | Vercel 이 가장 단순하다 |
| api | Node 상시 실행 | Railway · Fly · Render |
| DB | PostgreSQL 16 | Neon · Supabase · 호스팅사 부속 |

목표 비용은 **월 5만원 이하**다([[기술 스택 결정]]). 친구 몇 명 규모면 대부분 무료 티어에
들어가지만 **상시 실행 api 와 Redis 가 무료 티어의 경계**다.

### 환경변수

API (`apps/api/src/config/env.ts` 가 zod 로 검증한다 — 빠지면 **시작 자체가 실패한다**)

```
NODE_ENV=production
JWT_SECRET=            # 32자 이상. 로컬 것을 재사용하지 마라
DATABASE_URL=
WEB_ORIGIN=            # 배포된 웹 주소. CORS 가 이걸로 정확히 일치 검사한다
REDIS_URL=
STORAGE_BUCKET=
STORAGE_ENDPOINT=
STORAGE_ACCESS_KEY_ID=
STORAGE_SECRET_ACCESS_KEY=
STORAGE_REGION=auto
```

웹 (`apps/web/src/lib/env.ts`)

```
NEXT_PUBLIC_API_URL=            # 배포된 api + /api
NEXT_PUBLIC_IMAGE_BASE_URL=     # R2 공개 도메인 + 버킷 경로
```

> [!warning] `WEB_ORIGIN` 이 안 맞으면 화면이 조용히 죽는다
> `credentials: true` 라서 CORS 가 **정확한 오리진 일치**를 요구한다. 틀리면 SSR 은
> 되는데 클라이언트 fetch 만 전부 막혀서 "화면은 그려지는데 버튼이 안 먹는" 상태가
> 된다. 로컬에서 이걸로 시간을 썼다. → [[진행 현황판]] 경고

> [!warning] `NEXT_PUBLIC_IMAGE_BASE_URL` 은 공개 읽기가 되는 주소여야 한다
> 목록·상세의 썸네일은 `imageUrl(key)` 가 이 값에 키를 붙여 만든 **평범한 `<img>` 주소**다.
> 서명 URL 이 아니다. R2 버킷에 공개 읽기(또는 커스텀 도메인)를 열어야 사진이 보인다.
> 업로드는 서명 URL 이라 쓰기는 열지 않는다.

### 색인 — 해결됐다 (2026-07-26)

**전체 `noindex` 로 결정하고 구현했다.** 첫 배포는 친구 테스트이고, 테스트 데이터가
검색에 잡히면 나중에 지워도 캐시가 남는다.

`NEXT_PUBLIC_ALLOW_INDEXING` 하나로 갈린다. **기본값이 차단이고 `'true'` 일 때만 열린다** —
반대로 만들면 환경변수를 빠뜨린 배포가 곧 색인 허용이 되는데, 색인은 되돌리기가
비대칭이라 안전한 쪽이 기본이어야 한다.

| | 플래그 없음 (첫 배포) | `'true'` (실제 공개) |
| --- | --- | --- |
| `robots.txt` | `Disallow: /` | 공개 경로만 허용 |
| `/` · `/gallery` · `/pros` | noindex | **index** |
| `/login` · `/signup` | noindex | noindex |
| `(app)` 그룹 전체 | noindex | noindex |

켜도 갤러리는 열리고 의뢰는 닫힌다 — [[리스크 - 콜드스타트]]가 요구한 SEO 자산은
그대로 살아 있다.

> [!note] 로그인·가입을 따로 막았다
> 둘은 비로그인이 닿아야 해서 `(public)` 에 있는데, 그동안 그룹 레이아웃을 따라
> `index: true` 였다. 검색으로 데려올 가치가 있는 건 시공 사례이지 로그인 폼이 아니다.
> 페이지가 `'use client'` 라 `metadata` 를 못 달아서 레이아웃으로 감쌌다.

## 배포 후 첫날 겪을 것들

친구들이 쓰기 시작하면 바로 만나는 것들이다. 미리 알고 있으면 버그로 오해하지 않는다.

- **데모 계정으로 로그인할 수 없다.** `passwordHash` 가 일부러 null 이다(뒷문 방지).
  친구들은 직접 가입한다. 안내가 필요하다
- **관리자 계정을 프로덕션에서 따로 만들어야 한다.**
  `pnpm --filter @fitter/api db:seed:admin <email> <password>` — 로컬 비밀번호를 쓰지 마라
- **승인 큐가 즉시 찬다.** 친구가 "시공자"를 고르고 나가면 빈 프로필이 큐에 쌓인다.
  위험 신호로 구분은 되지만 쌓이는 건 안 막힌다 → [[열린 질문]] Q10
- **시공자는 승인 전까지 사례를 공개할 수 없다.** 관리자가 승인해줘야 갤러리에 뜬다.
  친구들끼리 테스트하려면 **승인해 줄 사람이 필요하다**
- **콜드스타트 화면을 보게 된다.** 사례가 0건이면 랜딩이 모집 모드로 바뀐다.
  의도된 것이지만 "비어 있다"는 인상을 준다 — 시드를 넣을지 정해야 한다
- **컨택 만료 배치는 Redis 워커가 돈다.** Redis 를 안 붙이면 만료가 영영 안 된다

## 에러 트래킹 — 어디에 붙였나 (2026-07-26)

**얹기만 해서는 빈 대시보드가 된다.** 이 프로젝트는 전역 필터가 `@Catch()` 로 모든
예외를 삼키고 있어서 Sentry 의 자동 수집이 볼 게 없다. 그래서 올리는 지점을 손으로 짚었다.

| 어디 | 무엇을 | 왜 거기여야 하나 |
| --- | --- | --- |
| `domain-exception.filter.ts` | 정체 모를 예외만 | 도메인 에러(404·409·403)는 **설계대로 동작한 결과**다. 같이 올리면 진짜 문제가 정상 트래픽에 묻힌다 |
| `thumbnail.queue.ts` `failed` | 워커 실패 | HTTP 를 안 거쳐 필터가 못 본다. 여기가 없으면 **썸네일이 조용히 안 뜬다** — 요청은 이미 200 으로 끝난 뒤다 |
| `instrumentation.ts` `onRequestError` | SSR 에러 | 갤러리·시공자 목록이 전부 SSR 이다 |
| `app/global-error.tsx` | 렌더 에러 | 없으면 React 가 삼킨 예외를 아무도 못 본다. **"그냥 하얗게 떠요" 제보가 이것이다** |

세 가지를 일부러 껐다. **트레이싱**(무료 티어 할당량을 성능 데이터로 태우면 정작
에러가 샘플링돼 사라진다), **`sendDefaultPii`**(본문에 비밀번호와 연락처가 오간다 —
응답에서 `phone` 을 지우고 에러 리포트로 새면 헛수고다), **세션 리플레이**(화면을
녹화하므로 수락된 컨택의 연락처가 영상으로 남는다).

`apps/api/src/instrument.ts` 가 **main.ts 의 첫 import** 여야 한다. Sentry 는 라이브러리를
로드 시점에 감싸서 계측하는데 순서가 밀리면 에러는 잡히되 "터지기 직전에 무슨 쿼리가
나갔나"가 통째로 빈다.

소스맵 업로드는 `SENTRY_ORG`·`SENTRY_PROJECT`·`SENTRY_AUTH_TOKEN` 셋이 있을 때만 돈다.
없으면 건너뛰고 빌드는 성공하므로 Sentry 프로젝트를 만들기 전에도 로컬이 깨지지 않는다.
