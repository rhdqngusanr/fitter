## Railway — 레포 연결만으로는 안 된다

**이게 이 배포에서 가장 헷갈리는 지점이다.** pnpm 워크스페이스 모노레포라
Railway 의 자동 감지가 무엇을 빌드할지 모른다. 레포 루트에 `apps/web` 과 `apps/api`
가 같이 있고, `packages/*` 를 **먼저 순서대로** 빌드해야 api 가 빌드된다.

그래서 `railway.json` 을 레포 루트에 두고 명령을 직접 적었다.

### `railway.json` 이 하는 일

```
buildCommand   prisma generate 후 shared → domain → api 순서로 빌드
preDeployCommand  prisma migrate deploy — 새 버전이 살아나기 전에 스키마를 맞춘다
startCommand   node apps/api/dist/main.js
healthcheckPath  /api/health
```

**`--filter "@fitter/api..."` 의 점 셋이 핵심이다.** 이게 "그 패키지와 그것이 의존하는
것들"을 뜻해서 `shared → domain → api` 를 위상 순서로 고르고 **웹은 빼놓는다.**
로컬에서 실제로 확인했다. `pnpm -r build` 로 하면 쓰지도 않을 웹까지 빌드한다.

**`prisma generate` 가 빌드보다 먼저여야 한다.** `PrismaService` 가 생성된 클라이언트를
상속하므로 없으면 타입이 없어 빌드가 깨진다. 로컬은 이미 생성돼 있어서 이 순서를
빠뜨려도 통과하는데 **빈 컨테이너에서만 터진다** — 로컬에서 재현되지 않는 종류다.

**마이그레이션을 시작 명령이 아니라 pre-deploy 로 뒀다.** 시작 명령에 넣으면 컨테이너가
재시작될 때마다 돌고, 마이그레이션이 실패하면 부팅 자체가 크래시 루프가 된다.

> [!warning] `preDeployCommand` 가 안 먹으면
> Railway 스키마가 이 필드를 거부하면 대시보드의 **Pre-Deploy Command** 칸에 같은
> 명령을 넣는다. 그것도 없으면 최초 1회만 Railway CLI 로 직접 돌린다.
> `prisma` 는 devDependency 라 Railway 가 prod 프루닝을 하면 사라질 수 있다 —
> 그때는 `apps/api/package.json` 에서 `prisma` 를 dependencies 로 옮긴다.

5. api 서비스 → Settings → Networking → **Custom Domain** 에 `api.xvsadfadsfasdfsdafsda.uk`

### Railway 환경변수

DB·Redis 는 **참조 변수**로 넣는다. 값을 복사하면 Railway 가 비밀번호를 회전할 때 끊긴다.

| 변수 | 값 |
| --- | --- |
| `NODE_ENV` | `production` |
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
| `REDIS_URL` | `${{Redis.REDIS_URL}}` |
| `WEB_ORIGIN` | `https://xvsadfadsfasdfsdafsda.uk` |
| `JWT_SECRET` | 직접 생성. **로컬 것을 재사용하지 마라** |
| `STORAGE_BUCKET` | `fitter-image` |
| `STORAGE_ENDPOINT` | R2 의 S3 API 엔드포인트 |
| `STORAGE_ACCESS_KEY_ID` | R2 토큰 |
| `STORAGE_SECRET_ACCESS_KEY` | R2 토큰 |
| `STORAGE_REGION` | `auto` |
| `SENTRY_DSN` | Sentry 프로젝트(Node) |

`PORT` 는 넣지 않는다. Railway 가 주입하고 `config/env.ts` 가 그걸 읽는다.

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

> [!danger] `WEB_ORIGIN` 이 틀리면 화면이 조용히 죽는다
> `credentials: true` 라 CORS 가 **정확한 오리진 일치**를 요구한다. 틀리면 SSR 은 되는데
> 클라이언트 fetch 만 전부 막혀서 "화면은 그려지는데 버튼이 안 먹는다". 로컬에서
> 이미 한 번 겪었다. 끝에 슬래시를 붙이지 마라.

## R2 · DNS

버킷 `fitter-image` → Settings → **Public access 를 커스텀 도메인 `img.xvsadfadsfasdfsdafsda.uk` 로** 연다.
`r2.dev` 는 Cloudflare 가 속도를 제한하므로 쓰지 않는다. 토큰은 **Object Read & Write**.

**공개 읽기가 열려야 사진이 보인다.** 목록·상세의 썸네일은 서명 URL 이 아니라
`imageUrl(key)` 가 만든 평범한 `<img>` 주소다. 업로드는 서명 URL 이라 쓰기는 열지 않는다.

DNS 는 Cloudflare 한 곳에서 관리한다 — 도메인을 Cloudflare Registrar 에서 샀으므로
네임서버를 옮길 필요가 없다. 실제로 들어간 레코드는 넷이다.

| Type | Name | Content | 프록시 |
| --- | --- | --- | --- |
| CNAME | `@` | `<해시>.vercel-dns-017.com` | **회색 (DNS only)** |
| CNAME | `api` | `<해시>.up.railway.app` | **회색 (DNS only)** |
| TXT | `_railway-verify.api` | `railway-verify=…` | — |
| R2 | `img` | 버킷 바인딩 | **주황 (Proxied)** |

> [!danger] 프록시를 켤 곳과 끌 곳이 갈린다 — 같은 화면 같은 열인데 규칙이 반대다
> Vercel 과 Railway 는 **각자 자기 인증서를 발급**받는다. 검증 요청이 원본까지 닿아야
> 하는데 주황색이면 Cloudflare 가 중간에서 받아버려서 발급이 끝나지 않는다.
> Vercel 은 `Proxy Detected` 라고 경고하고 Railway 는 그냥 대기 상태로 남는다.
>
> **`img` 만 반대다.** R2 커스텀 도메인은 Cloudflare 가 직접 서빙하는 구조라
> 프록시가 켜져 있어야 정상이다. 이걸 끄면 사진이 죽는다.

> [!warning] Railway 는 레코드가 **두 개**다
> CNAME 만 넣고 소유권 확인용 TXT 를 빠뜨리기 쉽다. TXT 가 없으면 인증서 발급이
> 영원히 대기 상태로 남는데, 화면에는 그냥 "확인 중"으로만 보인다.

> [!note] Railway 커스텀 도메인이 포트를 묻는다
> 기본으로 `8080` 이 채워져 있는데 `env.ts` 의 기본값은 3001 이라 헷갈린다.
> **그대로 두는 게 맞다** — 앱이 Railway 가 주입한 `PORT` 를 따라가므로 Railway 가
> 이미 아는 값이 채워진 것이다. 직접 바꾸면 헬스체크가 영원히 실패한다.

## 에러 트래킹 계정

Sentry 프로젝트를 **둘** 만든다. 하나로 합치면 웹 에러와 서버 에러가 섞여서
어느 쪽이 터졌는지 대시보드에서 안 갈린다.

| 프로젝트 | 플랫폼 | DSN 이 갈 곳 |
| --- | --- | --- |
| `javascript-nextjs` | Next.js | Vercel `NEXT_PUBLIC_SENTRY_DSN` |
| (Node 용) | Nest.js | Railway `SENTRY_DSN` |

> [!danger] Sentry 마법사를 실행하지 마라
> 온보딩 화면이 `npx @sentry/wizard` 를 "Recommended" 로 권한다. 그걸 돌리면
> `next.config.mjs` 를 덮어쓰고 `sentry.*.config.ts` 를 새로 만들어서
> 이미 붙여둔 `instrumentation.ts` · `instrumentation-client.ts` · `global-error.tsx` 와
> 충돌한다. **세션 리플레이를 꺼둔 설정까지 같이 날아간다.**
> 화면에서는 `Copy DSN` 만 누르고 `Skip setup` 으로 나온다.

프로젝트 설정에서도 **세션 리플레이를 켜지 마라.** 화면을 녹화하는 기능이라
수락된 컨택의 연락처가 영상으로 남는다 — 응답에서 `phone` 키를 지운 의미가 없어진다.

## 친구들에게 열기 전에 남은 것

**rate limit.** [[배포 준비 상태]] 참고. 신고는 비로그인도 낼 수 있고 인정되면 대상이
즉시 비공개가 된다.

**키 교체.** 배포 중에 `JWT_SECRET` 과 R2 키가 대화창에 노출됐다. 각각 1분이다 —
`JWT_SECRET` 은 새로 만들어 Railway 변수만 갈면 되고(기존 세션이 끊기는 게 전부),
R2 키는 토큰을 지우고 같은 설정으로 다시 발급하면 된다.
