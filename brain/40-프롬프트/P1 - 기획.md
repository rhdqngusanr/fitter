## P1-1. PRD 작성

```
CLAUDE.md를 읽고, brain/ 폴더에서 아래 노트들을 읽어줘.
- brain/10-제품/서비스 정의.md
- brain/10-제품/문제 정의.md
- brain/10-제품/타겟 - 고객.md
- brain/10-제품/타겟 - 시공자.md
- brain/10-제품/경쟁 지형.md
- brain/10-제품/MVP 범위.md
- brain/10-제품/리스크 레지스터.md
그리고 design/ 폴더의 시안을 참고해줘.

그 내용을 근거로 brain/70-산출물/PRD.md 를 작성해줘.

[포함할 섹션]
1. 문제 정의 — 고객 측 고통과 시공자 측 고통을 분리해서
2. 해결 가설 — 왜 "사진 기반 양방향 매칭"이 그 고통을 푸는가
3. 타겟 사용자 페르소나 2명. 각각 하루 일과와 현재 대안 포함
4. 경쟁 분석 — 오늘의집·집닥·숨고와 비교한 포지셔닝 표.
   축은 (매칭 단위: 업체/개인), (입력 방식: 폼/사진), (가격 투명성), (중개 마진)
5. 핵심 사용자 여정 2개를 시퀀스로
   - 고객: 가입 → 사진 수집 → 의뢰 등록 → 시공자 컨택 받음 → 수락 → 연락
   - 시공자: 가입 → 승인 → 포트폴리오 등록 → 의뢰 탐색 → 제안 → 수락됨
6. MVP 기능 명세 — 각 기능마다 [사용자 가치] [수용 기준(Given/When/Then)] [제외 범위]
7. 비기능 요구사항 — 이미지 용량/개수 제한, 목록 응답 시간 목표,
   동시 접속 가정, 개인정보 보관 정책
8. 성공 지표 — 포트폴리오 프로젝트이므로 실사용 지표 대신
   "기술적으로 증명하려는 것" 3가지로 대체해서 정의
9. 리스크와 완화책 — brain의 리스크 노트를 근거로, 최소 5개
10. 2차 로드맵 — 가격 산출, 리뷰, 안전결제. 각각 왜 2차인지 한 줄 근거

[작성 원칙]
- brain 노트에 없는 내용을 추측으로 채우지 마. 검증 안 된 가정은 "가정:"이라고 명시
- 표와 불릿을 남발하지 말고 판단이 필요한 부분은 문장으로 논증
- 다 쓰고 나서, 이 PRD에서 가장 약한 논리 3개를 스스로 지적해줘

완료 조건: brain/70-산출물/PRD.md 파일이 생성되고, 위 10개 섹션이 모두 채워져 있을 것.
```

## P1-2. 유저 스토리와 수용 기준

```
brain/70-산출물/PRD.md와 brain/20-도메인/ 폴더의 엔티티 노트들을 읽고
brain/70-산출물/유저 스토리.md를 작성해줘.

[형식] 에픽 단위로 묶고, 각 스토리는:
- ID (US-001)
- "나는 [역할]로서 [목적]을 위해 [기능]을 원한다"
- 수용 기준: Given/When/Then 3개 이상
- 예외 케이스: 최소 2개 (빈 값, 권한 없음, 중복, 네트워크 실패 등)
- 관련 화면 ID
- 우선순위: Must / Should / Could

[에픽 목록]
E1 인증·역할, E2 고객 의뢰 등록, E3 시공자 포트폴리오,
E4 탐색·필터, E5 컨택·매칭, E6 신고·관리, E7 알림

[특히 꼼꼼하게]
- E5 컨택의 상태 전이. brain/20-도메인/상태머신 - 컨택.md 를 근거로,
  어떤 상태에서 어떤 상태로 갈 수 있고 누가 그 전이를 일으키는지.
  상태 다이어그램을 mermaid로 그려줘.
- E2에서 사진 출처 URL 필수 검증 로직

완료 조건: 모든 Must 스토리에 Given/When/Then과 예외 케이스가 있을 것.
```

## P1-3. MVP 범위 잠그기

```
brain/70-산출물/PRD.md, brain/70-산출물/유저 스토리.md, brain/10-제품/MVP 범위.md 를 읽고 나에게 반문해줘.

나는 이걸 개발 포트폴리오로 만든다. 혼자, 실제 개발 기간은 4~6주로 잡고 있다.

[해줄 일]
1. Must로 표시된 스토리를 전부 나열하고, 각각 예상 개발 시간을 보수적으로 추정
2. 합계가 4~6주를 넘으면, 어떤 걸 Should로 내려야 하는지 근거와 함께 제안
3. 반대로 "포트폴리오 관점에서 이건 빼면 안 된다"는 것도 지적해줘.
   (brain에서 기술 하이라이트로 지목한 것: 이미지 파이프라인, 컨택 상태 머신)
4. 최종 확정 범위를 brain/70-산출물/PRD.md에 반영하고, 잘라낸 것은 brain/70-산출물/백로그.md로 옮겨줘

나에게 아부하지 말고, 범위가 과하면 과하다고 말해줘.
```

**결과 반영:** 확정된 범위를 [[MVP 범위]] 노트에 반영하고 status를 `확정`으로 바꾼다.
