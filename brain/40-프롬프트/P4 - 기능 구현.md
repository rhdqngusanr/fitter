# P4 - 기능 구현

> **하나씩** 실행한다. 각각 plan mode로 계획 먼저 → 승인 → 구현 → 커밋.
> 모든 프롬프트 앞에 붙인다: `CLAUDE.md, brain/70-산출물/ERD.md, brain/70-산출물/API 명세.md를 먼저 읽어줘.`

## P4-1. 인증과 역할 분리

```
CLAUDE.md, brain/70-산출물/API 명세.md, brain/50-결정/ADR-002 - 인증과 권한 모델.md,
brain/30-설계/권한 모델.md 를 먼저 읽어줘.

인증과 역할 시스템을 구현해줘.

[범위]
- 이메일 회원가입/로그인, 소셜 로그인 1개(카카오 우선)
- 가입 직후 역할 선택 온보딩 (CUSTOMER / PRO)
- 역할별 기본 리디렉션
- 미들웨어 레벨 라우트 보호
- 소유자 기반 권한 검사 유틸 (재사용 가능한 형태로)
- 로그아웃, 세션 만료 처리

[중요]
- 권한 검사는 ADR-002에서 정한 레이어에서만. 여러 군데 흩뿌리지 말 것
- PRO는 가입 직후 is_approved=false. 미승인 상태에서 가능한 액션을 명확히 제한
  (가능: 프로필 작성, 포트폴리오 작성·저장, 의뢰 열람
   불가: 포트폴리오 공개, 컨택 요청 발송, 시공자 목록 노출)

완료 조건:
- 세 역할(비로그인/CUSTOMER/PRO)로 각 보호 라우트에 접근하는 테스트가 모두 통과
- 미승인 PRO가 포트폴리오를 공개하려 하면 403
```

## P4-2. 이미지 업로드 파이프라인 ★

> **기술 하이라이트 1번.** 면접에서 제일 많이 물어볼 부분. 공들일 것. → [[이미지 파이프라인]]

```
brain/20-도메인/이미지 파이프라인.md 와
brain/10-제품/리스크 - 레퍼런스 사진 저작권.md 와
brain/70-산출물/API 명세.md의 이미지 업로드 섹션을 읽어줘.

이미지 업로드 파이프라인을 구현해줘. 의뢰 사진과 포트폴리오 사진이 공유하는 공통 모듈로.

[요구사항]
1. 클라이언트 → 서명 URL 요청 → 스토리지 직접 업로드 → 서버에 메타데이터 등록
2. 클라이언트 검증: 확장자(jpg/png/webp/heic), 용량(장당 10MB),
   개수(의뢰 10장 / 포트폴리오 15장)
3. 클라이언트 리사이즈·압축 후 업로드 (원본이 4000px면 그대로 올리지 말 것)
4. 서버 재검증 — 매직 넘버로 실제 파일 타입 확인. 확장자만 믿지 말 것
5. 썸네일 파생: 목록용 400px, 상세용 1200px, 원본 보관
6. 업로드 진행률 표시, 개별 취소, 실패 시 재시도
7. 드래그앤드롭 + 순서 변경(대표 사진 지정)
8. 고아 파일 정리 — 업로드는 됐는데 등록이 안 된 파일 처리 전략을 제안하고 구현
9. EXIF 제거 (위치정보 개인정보 문제)

[의뢰 사진 전용 추가]
- 출처 구분 필수: SELF / EXTERNAL
- EXTERNAL이면 source_url 입력 필수, URL 형식 검증
- 등록 화면에 저작권 안내 문구 노출

구현 전에 전체 시퀀스 다이어그램을 mermaid로 그려서 보여주고 승인받아줘.

완료 조건:
- 10MB 초과, 잘못된 확장자, 확장자 위조 파일이 모두 거부되는 테스트
- 업로드 중 취소 시 스토리지에 잔여물이 남지 않는 것 확인
```

## P4-3. 고객 — 레퍼런스 의뢰 등록

```
brain/20-도메인/엔티티 - ReferenceRequest.md 와 brain/20-도메인/확장 규약.md,
brain/70-산출물/ERD.md, brain/70-산출물/API 명세.md를 읽어줘. design/ 시안을 참고해줘.

고객이 인테리어 레퍼런스 의뢰를 등록하는 기능을 구현해줘.

[입력 필드 — 확장 규약 준수]
제목, 상세 설명, 사진 1~10장(P4-2 모듈 사용, 출처 정보 포함),
공종 다중 선택(WorkCategory 코드 테이블에서), 평수(숫자 입력, ㎡ 자동 변환 표시),
주거형태, 지역(시도 → 시군구 2단계), 희망 시공 시기(기간 범위),
거주 중 여부, 자재 등급 선호(선택), 예산 범위(선택)

[구현]
- 다단계 폼(3~4스텝). 각 스텝 이탈해도 서버 draft로 임시저장
- 클라이언트·서버 양쪽 검증 (동일 스키마 공유)
- 낙관적 UI, 에러 시 롤백
- 등록 완료 후 상세 페이지로 이동
- 수정/삭제(soft delete), 공개/비공개 토글

[주의]
- 사용자는 인테리어 용어를 모른다. 용어 대신 선택지와 사진으로 묻는다
- 예산 범위는 선택이지만 입력 유도 UX를 넣어줘. 2차 견적 기능의 핵심 데이터다
- DRAFT 상태가 어떤 목록에도 노출되지 않게. 이걸 빠뜨리기 쉬우니 테스트로 잡아줘

완료 조건: 필수값 누락, 사진 0장, 잘못된 평수(0 이하, 500 초과)가 모두 차단되는 테스트 통과.
```

## P4-4. 시공자 — 포트폴리오 등록

```
brain/20-도메인/엔티티 - PortfolioItem.md 와 brain/20-도메인/엔티티 - User와 역할.md,
brain/70-산출물/ERD.md, design/ 시안을 읽어줘.

시공자 포트폴리오 등록·관리와 프로필 기능을 구현해줘.

[포트폴리오]
제목, 설명, 사진(P4-2 모듈, 최대 15장, 대표 지정, BEFORE/AFTER/PROCESS 구분),
공종 다중 선택, 시공 평수(숫자), 주거형태, 시공 지역, 작업 기간(일),
시공 연월, 실제 비용 공개 여부 + 비용(선택. 공개 시 신뢰도 뱃지)

[프로필]
상호/활동명, 소개, 경력 연차, 보유 공종, 활동 가능 지역(다중),
사업자등록번호(선택), 인증 서류 업로드 → 관리자 승인 대기

[구현]
- 포트폴리오 CRUD, 순서 변경, 임시저장
- 프로필 완성도 표시 (채울수록 노출 가산점을 눈에 보이게)
- 시공자 공개 프로필 페이지 (포트폴리오 갤러리 형태)
- 승인 대기 안내 화면 (빈 화면을 만들지 않기 위해)

[주의]
- 비용 공개 필드는 2차 가격 기능의 실측 데이터원이다.
  금액, 공종, 평수, 시공 연월, 자재등급, 지역 코드를 함께 정규화해서 저장할 것
- 시공자는 모바일에서 사진 15장을 빠르게 올린다. 여기서 느리면 이탈한다

완료 조건: 미승인 PRO는 포트폴리오를 저장할 수 있으나 공개되지 않는 것을 테스트로 검증.
```

## P4-5. 탐색 — 목록, 필터, 검색

```
brain/70-산출물/API 명세.md, brain/70-산출물/ERD.md, brain/10-제품/리스크 - 콜드스타트.md 를 읽어줘.

탐색 기능을 구현해줘. 세 개의 목록이 있다.
1. 의뢰 목록 (시공자가 봄)
2. 시공자 목록 (고객이 봄)
3. 포트폴리오 갤러리 (누구나 봄, 비로그인 포함)

[공통 요구사항]
- 커서 페이지네이션 + 무한 스크롤
- 필터: 공종(복수), 지역(복수), 평수 범위, 주거형태, 정렬(최신/인기)
- 필터 상태를 URL 쿼리스트링에 동기화 (공유·뒤로가기 가능)
- 스켈레톤 로딩, 빈 상태, 에러 상태
- 이미지는 썸네일만 로드. lazy loading + blur placeholder
- 포트폴리오 갤러리는 SSR로 SEO 대응 (검색 유입이 콜드스타트 대응이다)

[성능]
- 각 필터 조합에 대해 실제 실행 쿼리와 EXPLAIN 결과를 보여줘
- 필요한 인덱스를 추가하고, 왜 그 인덱스인지 설명해줘
- 시드 데이터 1만 건을 넣고 응답 시간을 측정해서 리포트해줘

[콜드스타트 대응]
- 결과가 0건일 때 필터를 자동으로 완화한 추천을 보여주는 로직
  (예: 지역을 인접 시군구까지 확장)

완료 조건: 1만 건 시드 상태에서 모든 필터 조합의 목록 응답이 300ms 이내.
```

## P4-6. 컨택 상태 머신 ★

> **기술 하이라이트 2번.** → [[상태머신 - 컨택]]

```
brain/20-도메인/상태머신 - 컨택.md 와 brain/20-도메인/엔티티 - ContactRequest.md,
brain/30-설계/권한 모델.md, brain/70-산출물/유저 스토리.md의 E5를 읽어줘.

컨택(매칭) 기능을 구현해줘.

[두 방향]
- 시공자 → 의뢰: "제안하기" (PRO_TO_REQUEST)
- 고객 → 시공자: "문의하기" (CUSTOMER_TO_PRO)

[상태 머신]
REQUESTED → ACCEPTED / DECLINED / CANCELLED / EXPIRED

[규칙]
- 상태 전이는 도메인 레이어의 명시적 함수로만. 직접 UPDATE 금지
- 각 전이의 주체를 강제 (요청자만 CANCELLED, 수신자만 ACCEPTED/DECLINED)
- 불가능한 전이 시도 시 도메인 에러
- 7일 무응답이면 EXPIRED. 배치 방식과 조회 시점 판정 중
  어느 쪽이 나은지 판단해서 선택하고 근거를 남겨줘
- 동일 상대에게 중복 요청 방지 (진행 중 요청이 있으면 차단)
- 하루 요청 개수 제한 (스팸 방지)

[연락처 공개 — 가장 중요]
- ACCEPTED 이전에는 연락처가 API 응답에 절대 포함되지 않아야 한다.
  컨트롤러마다 if문으로 막지 말고 응답 직렬화 레이어에서 한 번에 강제해줘.
- 이를 검증하는 테스트를 반드시 작성. 화면에 안 보이는 것과 응답에 없는 것은 다르다
- ACCEPTED 시점에 양쪽 모두에게 상대 연락처 공개

[구현]
- 상태 머신을 테스트하기 쉬운 순수 함수로 분리
- 컨택 목록 화면 (보낸 요청 / 받은 요청 탭)
- 상태 변경 시 도메인 이벤트 발행 (P4-7에서 알림이 소비)

완료 조건:
- 모든 유효/무효 전이 조합을 검증하는 단위 테스트 (최소 15케이스)
- REQUESTED 상태에서 응답 JSON에 phone 키가 존재하지 않음을 검증하는 통합 테스트
```

## P4-7. 알림, 신고, 관리자

```
brain/10-제품/리스크 - 레퍼런스 사진 저작권.md 를 읽어줘.
아래 세 기능을 구현해줘. 각각 별도 커밋으로.

[1. 알림]
- 인앱 알림 목록, 읽음 처리, 안읽음 뱃지
- 트리거: 컨택 요청 수신, 수락/거절, 시공자 승인 완료, 신고 처리 결과
- 도메인 이벤트를 구독하는 방식으로 느슨하게 결합
- 이메일 발송은 인터페이스만 두고 구현은 콘솔 출력으로 (나중에 교체 가능하게)

[2. 신고]
- 대상: 의뢰, 포트폴리오, 시공자, 사용자
- 사유 코드: 저작권 침해, 허위 정보, 스팸, 부적절한 내용, 기타
- 저작권 침해 신고는 별도 플로우 — 권리자 정보 입력, 즉시 비공개 처리 옵션,
  ReferenceImage의 is_takedown_requested 플래그 연동
- 중복 신고 방지, 신고 남용 방지

[3. 관리자]
- 시공자 승인 대기 목록 / 승인 / 반려(사유 입력)
- 신고 처리 큐 (조치: 무시 / 경고 / 비공개 / 계정 정지)
- 조치 이력 로그 (누가 언제 무엇을)
- 관리자 계정은 시드로만 생성. 가입 경로 없음

완료 조건: 관리자 API에 일반 사용자가 접근 시 전부 403인 것을 검증하는 테스트.
```

## P4-8. 테스트 보강

```
프로젝트 전체를 스캔하고 brain/70-산출물/테스트 전략.md를 작성한 뒤 빠진 테스트를 채워줘.

[먼저 분석]
1. 현재 커버리지와, 커버리지 숫자와 무관하게 "위험한데 안 덮인 곳" 목록
2. 각 위험 지점의 실패 시나리오 (구체적 입력 → 잘못된 결과)

[반드시 테스트가 있어야 하는 곳]
- 권한: 모든 보호 엔드포인트 × 모든 역할 조합
- 연락처 노출: 컨택 상태별로 응답에 phone이 포함/미포함되는지
- 상태 머신: 무효 전이 전부
- 이미지 업로드: 파일 타입 위조, 용량 초과, 개수 초과
- 입력 검증: 경계값 (평수 0, 음수, 500 초과 / 사진 0장, 11장)
- 커서 페이지네이션: 중복·누락 없이 전체를 순회하는지
- DRAFT 의뢰가 공개 목록에 노출되지 않는지

[하지 말 것]
- 커버리지 숫자만 올리는 의미 없는 테스트
- 구현 세부사항에 결합된 테스트

완료 조건: 위 7개 영역이 모두 덮이고, 전체 테스트가 통과할 것.
```
