# 보조 프롬프트

> 막혔을 때 그때그때 던지는 것들. Phase에 속하지 않는다.

## 계획 검토

```
방금 세운 계획에서 내가 놓친 것, 순서가 잘못된 것, 과한 것을 지적해줘.
동의하는 부분은 말하지 말고 문제만 말해줘.
```

## 구현 후 자기 검증

```
방금 만든 코드를 다시 읽고, 아래를 스스로 점검해줘.
1. 요구사항 중 빠뜨린 것
2. 에러 케이스 중 처리 안 한 것
3. CLAUDE.md와 brain/20-도메인/확장 규약.md 를 어긴 곳
4. 이 코드가 깨질 수 있는 입력 3가지
문제가 있으면 고치고, 없으면 "없음"이라고만 답해줘.
```

## 디버깅

```
[에러 메시지 붙여넣기]

바로 고치지 말고 먼저:
1. 이 에러가 발생하는 정확한 조건
2. 가능한 원인 3개와 각각의 확률
3. 각 원인을 확인하는 최소 비용의 방법
을 말해줘. 내가 원인을 확정한 뒤에 고치자.
```

## 리팩터링

```
[파일 경로]를 리팩터링해줘.
단, 동작은 100% 동일해야 한다. 리팩터링 전후로 테스트가 모두 통과해야 한다.
바꾼 것마다 왜 바꿨는지 한 줄씩 설명해줘.
동작을 바꾸는 제안이 있으면 코드로 만들지 말고 별도로 말해줘.
```

## 커밋

```
지금 변경사항을 논리 단위로 나눠서 커밋해줘.
한 커밋에 여러 관심사를 섞지 마.
커밋 메시지는 Conventional Commits 형식, 본문에 왜 이렇게 했는지 한국어로 2줄.
```

## 세션 마무리 (중요)

> 세션을 끝낼 때 반드시 던진다. 이게 없으면 다음 세션이 처음부터 시작한다.

```
brain/00-허브/세션 부팅 프로토콜.md 의 4단계를 수행해줘.

1. brain/00-허브/진행 현황판.md 의 해당 항목 상태 갱신
2. 새로 내린 결정이 있으면 brain/50-결정/ 에 ADR 노트 생성 + ADR 인덱스에 링크
3. 결정하지 못하고 미룬 것은 brain/00-허브/열린 질문.md 에 추가
4. 도메인이 바뀌었으면 도메인 용어집과 해당 엔티티 노트 수정
5. brain/60-로그/ 에 오늘 날짜 세션 로그 작성
   (무엇을 했는가 / 무엇을 결정했는가 / 무엇이 막혔는가 / 다음에 무엇을)
6. 새로 만든 노트가 어디서도 링크되지 않은 고아 노트가 아닌지 확인

노트 형식은 brain/90-규약/노트 작성 규칙.md 를 따라줘.
```

## 볼트 건강 점검

```
brain/ 폴더 전체를 스캔해서 아래를 보고해줘.

1. 어디서도 링크되지 않는 고아 노트
2. 존재하지 않는 노트를 가리키는 깨진 위키링크
3. 프론트매터가 없거나 형식이 틀린 노트
4. "## 연결" 섹션이 없는 노트
5. 같은 내용이 두 노트에 중복으로 적힌 곳
6. status가 미정/보류인데 열린 질문.md 에 대응 항목이 없는 노트

문제만 나열하고, 고칠지는 내가 정한다.
```
