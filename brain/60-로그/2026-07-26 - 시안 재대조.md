# 2026-07-26 - 시안 재대조

## 무엇을 했는가

`design/`의 시안 9개를 하나씩 열어 구현과 맞췄다. 10회에 걸쳐 한 번에 한 파일씩 했고
커밋도 파일당 하나다(`0306cf7` ~ `4204496`).

사용자가 "처음부터 기획한 디자인 시안과 똑같이 안 만들고 멋대로 만들었다"고 지적한 데서
시작했다. [[시안 대조 결과]]에 1차 대조 기록이 이미 있었지만 그건 **구조만** 맞춘 것이었고,
헤더·폭·타이포·2단 구성·hover 상태는 손대지 않은 채였다.

작업 순서를 뿌리부터 잡았다. 화면을 하나씩 고쳐도 토큰과 공용 부품이 어긋나 있으면
다음 화면에서 또 갈라지기 때문이다.

## 무엇을 결정했는가

**시안끼리 어긋날 때는 화면 시안을 따른다.** 디자인 시스템의 타입 스케일은 `display` 를
40px 로 정하고 용도를 "랜딩 히어로 1개"라고 못 박았는데 `G-01 랜딩` 의 h1 은 52px 다.
사용자가 비교하는 건 그 화면이므로 화면 시안을 택했고, 예외 크기는 `components.css` 의
화면 전용 클래스 한 곳에 모았다. 시안끼리 어긋난다는 사실 자체는 [[시안 검수 결과]] 11번에
결함으로 올렸다.

**타이포 토큰은 시안 `:root` 에 먼저 넣고 사본으로 가져왔다.** 시안 02 TYPE 표가 이미
`--text-h1` 같은 이름을 적어두고 푸터가 `type 6` 으로 세고 있었는데 선언만 빠져 있었다.
정본이 자기 자신과 어긋난 경우였고, `pnpm qc` 의 `token-invented` 가 요구하는
"시안에 먼저 넣고 가져와라" 순서를 그대로 따랐다.

**크기만 변수로 두지 않는다.** 시안의 한 행은 `40/800/1.2/-0.03em` 네 값이다. 크기만
토큰으로 만들면 굵기·행간·자간이 또 갈라진다. 네 값을 묶은 `.t-display` ~ `.t-caption`
클래스를 두고 화면은 클래스만 쓴다.

**`button { min-height: 44px }` 를 걷어냈다.** 전역으로 강제하던 게 시안을 어기고 있었다 —
시안의 칩은 36px, sm 버튼은 32px 인데 전부 44px 로 부풀어 있었다. 시안이 정한 규칙은
"**모바일** 최소 터치 타깃 44px"이고 그래서 모바일 주 버튼이 48~52px 다. 크기는 컴포넌트가 정한다.

**컴포넌트 스타일을 CSS 로 뺐다.** 시안이 버튼·카드·칩마다 `style-hover` 와 `:active`,
`focus-visible` 를 그려뒀는데 React 인라인 스타일로는 그 상태를 쓸 수 없다. 그래서 구현이
hover 를 통째로 빠뜨리고 있었고, 눌리는 느낌이 없는 화면이 "시안과 다르다"의 큰 부분이었다.
클래스 이름은 시안이 적어둔 것(`.btn` · `.card-photo`)을 그대로 쓴다.

**폭을 세 종류로 줄였다.** `max-width` 가 680·720·880·1120 으로 제각각이라 화면을
넘어갈 때마다 본문이 좌우로 흔들렸다. `.shell`(1280) · `.shell--content`(1000) ·
`.shell--form`(680) 셋만 남겼고 셋 다 시안에 실제로 있는 값이다.

**C-06 을 비로그인 공개로 바꿨다 — [[화면 목록]]과 다른 결정이다.** 화면 목록은 C-06 을
`로그인(CUSTOMER)`로 적었지만 같은 표에서 C-07 은 `비로그인 공개`다. 목록이 로그인
전용이면 공개된 프로필로 가는 길이 없어진다. 포트폴리오가 공개인데 만든 사람을 찾는
목록이 비공개인 것도 앞뒤가 안 맞는다. 화면 목록의 접근 칸을 고쳤다.

**없는 숫자는 만들지 않는다.** 시안이 그린 `시공 87건 · 응답 3시간 · 수락률 67%` 는
집계가 하나도 없다. `등록한 사례 2건` 처럼 우리가 아는 것만 쓰고, 리뷰는 `준비 중` 이라고
적는다. 숫자 하나를 지어내면 그 카드의 나머지도 못 믿게 되고, 이 화면의 목적이
"맡겨도 되는 사람인지 판단"이라 근거가 거짓이면 화면 자체가 무의미해진다.

**중복 제안·중복 컨택은 에러가 아니라 상태로 다룬다.** 서버가 409 로 막으면 빨간 글씨
대신 `제안 보냄 · 응답 대기` 뱃지와 "이미 제안한 의뢰입니다"를 보여주고 컨택으로 보낸다.

**시공자의 공개 식별자는 `userId` 다.** 새로 만든 `/pros` 가 `userProfileId` 를 쓰다가
포트폴리오 API 의 `pro.id`(=`userId`)와 갈라져 링크가 404 가 났다. 같은 개념에 두 번째
이름을 만들지 않는다. e2e 로 고정했다.

## 없던 화면 둘을 만들었다

**`/jobs` (P-04 · P-05).** 이게 없어서 **서비스가 한쪽으로만 돌고 있었다** — 고객이 의뢰를
올려도 시공자가 볼 방법이 없었다. `GET /reference-requests` 는 진작 있었는데 화면이 없었다.
브라우저에서 한 바퀴 통과시켰다: C-01 로 의뢰 공개 → `/jobs` 에서 열람 → 제안 전송 →
`1,800,000원 제안` 이 붙은 컨택 상세 도착.

**`/pros` (C-06 · C-07).** 이건 **API 도 없었다.** `GET /pros` 와 `GET /pros/:id` 를
새로 만들었다(`apps/api/src/modules/pros/`). 스키마는 건드리지 않았다 — 이미 있는
`ProProfile` 과 `PortfolioItem` 을 시공자 기준으로 다시 묶는 읽기 전용 조회다.
공개 조건은 포트폴리오와 **정확히 같은 문장**이어야 한다(승인됨 + 휴면 아님) — 갈라지면
갤러리에는 보이는데 프로필은 404 인 상태가 생긴다. e2e 6건으로 그걸 고정했다.

## 브라우저에서 잡은 결함 9건

**시각 정렬보다 이쪽이 값졌다.** 전부 타입도 테스트도 통과하던 것들이다.

1. **P-02** — 화면은 "공개해도 승인 전엔 갤러리에 안 뜬다"고 했는데 서버는 **공개 자체를
   막는다**(403, `publish` 는 승인된 시공자 전용). 미승인 계정에게 `사례 공개하기` 는
   **누를 때마다 실패하는 버튼**이었다. 1차 대조 노트와 `내 사례` 배너도 같은 오해를
   담고 있어 셋 다 고쳤다.
2. **P-02** — 프로필 조회를 초안 생성과 같은 effect 에 둬서, 초안이 만들어져 `draftId` 가
   바뀌는 순간 정리 함수가 아직 날아오는 중이던 응답을 버렸다. 상태가 영원히 `unknown` 에
   머물러 공개 버튼이 그대로 남았다.
3. **G-03** — `/portfolios/new` 에서 튕겨온 사람이 **고객**을 고르면 `next` 를 그대로 따라
   다시 거기로 가고 그 화면의 역할 가드가 또 홈으로 튕겼다. 역할을 골랐는데 아무 데도
   도착하지 못한다. 1차에서 고친 버그("시공자를 골라도 홈으로 튕겼다")와 같은 종류다.
4. **C-07** — 시공자 식별자가 둘이라(`userProfileId` vs `userId`) `프로필 전체 보기` 가 404.
5. **C-07** — 상호가 빈 프로필이 목록 첫 줄에 **빈 카드**로 떴다. 역할을 고르면 프로필 행이
   자동 생성되므로 `businessName` 이 빈 계정이 존재한다.
6. **C-05** — 사진이 2장이면 모자이크가 큰 칸과 작은 칸에 **같은 사진**을 걸었다.
   시안 배치가 3장 이상을 전제한다.
7. **C-05** — 모자이크 작은 칸에 시공 전/후 라벨이 없어서 나란히 걸린 사진이 무엇인지
   알 수 없었다. before/after 대비는 이 서비스에서 실력을 가장 잘 보여주는 장치다.
8. **M-02** — 액션 자리를 나누며 일반 유틸리티(768px)를 썼는데 이 화면은 900px 에서
   갈라진다. 그 사이 구간에서 **버튼이 두 벌** 보였을 것이다.
9. **P-02** — 숫자 인풋의 플레이스홀더를 `24평` 으로 썼다. 숫자 칸인데 단위까지 칠 수
   있는 것처럼 보인다. `pnpm qc` 가 잡았고 지적이 맞았다.

## 도구를 두 번 고쳤다

**`pnpm qc` 에 타이포 검사를 추가하고 error 로 승격했다.** 도입할 때 101건이었고 화면을
하나씩 옮겨 0이 됐다. warn 으로 두면 "나중에"가 계속 미뤄지므로 0이 된 순간에 잠갔다.
일부러 `fontSize: 22` 를 넣어 error 로 잡히는 것을 확인했다.

**확장 규약 검사기의 오탐을 고쳤다.** 줄 단위로 보고 있어서 Prettier 가 JSX 속성을 여러
줄로 쪼갠 멀쩡한 숫자 인풋을 자유 텍스트로 잡았다. 태그가 닫힐 때까지 이어 붙여 보게 하고,
평수 여부를 라벨뿐 아니라 인풋 자신의 `aria-label` 로도 판단하게 했다 — 줄 수에 기대는
판정을 하나 줄인 것이다. 일부러 `type="text"` 로 바꿔 여전히 잡는 것을 확인했다.

## 환경에서 배운 것 둘

**`next build` 를 개발 서버가 켜진 상태로 돌리면 `.next` 가 덮여서 하이드레이션이 죽는다.**
`main-app.js` 가 404 가 되고 **화면은 그려지는데 아무 버튼도 안 먹는다.** 원인을 찾는 데
30분을 썼다. 빌드 후에는 개발 서버를 다시 띄운다.

**API 의 `WEB_ORIGIN` 이 `http://localhost:3000` 이라 다른 포트에서는 클라이언트 fetch 가
CORS 로 막힌다.** `더 보기` 같은 클라이언트 동작을 확인하려면 웹이 3000번이어야 한다.
`.claude/launch.json` 의 `web-dev` 를 그렇게 고정했다.

## 검증

`pnpm typecheck` · `lint` · `qc`(0 error) · `test`(174건) · `build` 전부 통과.
테스트는 168 → 174로 늘었다(`/pros` e2e 6건).

화면은 전부 **1280px 과 390px 두 프레임에서 계산된 스타일로 실측**했다. 스크린샷이 아니라
`getComputedStyle` 로 봤다 — 시안이 숫자로 적어둔 규격은 숫자로 대조하는 게 맞다.

## 남은 것과 그 이유

못 만든 상태는 전부 **API 가 없어서**다. 화면 문제가 아니다. 목록은 [[시안 대조 결과]]에 있고,
그중 둘은 [[열린 질문]]에 올렸다 — Q8(`이용 방법` 화면), Q9(임시저장 복원).

**시공자 프로필 등록 화면(P-01)이 없다는 게 이번에 두 번 드러났다.** G-03 이 "다음 화면:
프로필 등록"이라고 약속하는데 그 화면이 없어서 `/portfolios/new` 로 보내고 있고,
프로필이 없으면 승인도 없으므로 사례를 영원히 공개할 수 없다. `design/` 에 시안이 없어
이번 범위 밖이었다.
