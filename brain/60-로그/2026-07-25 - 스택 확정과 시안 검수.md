# 2026-07-25 - 스택 확정과 시안 검수

## 무엇을 했는가

GitHub 저장소를 연결하고 `docs/` 목업을 공개 배포 준비 상태로 올렸다. `brain/`은 사업 기획 자료라 `.gitignore`로 제외했다. 저장소가 public이기 때문이다.

기술 스택을 확정하고 ADR-001을 썼다. 그다음 [[P0 - 디자인 시안]] P0-4 시안 자체 검수를 수행했다. `design/`의 시안 8개 약 4,400줄을 전수 감사해 [[시안 검수 결과]] 10건을 남겼다.

이어서 P1-1 PRD를 `brain/70-산출물/PRD.md`로 작성했다. 10개 섹션을 채우고 마지막에 이 PRD에서 가장 약한 논리 3개를 스스로 지적해 붙였다.

그다음 P1-2 유저 스토리를 `brain/70-산출물/유저 스토리.md`로 작성했다. 에픽 7개에 스토리 39개(Must 30 / Should 7 / Could 2)이고, 모든 Must에 Given/When/Then 3개 이상과 예외 케이스 2개 이상을 붙였다. 컨택 상태 전이도를 mermaid로 그리고 주체 규칙 표를 함께 뒀다.

## 무엇을 결정했는가

**기술 스택은 B — Next.js + NestJS + PostgreSQL + S3호환.** 근거는 `brain/50-결정/ADR-001 - 기술 스택 선정.md`에 전문으로 남겼다. 요지는 세 후보 모두 100배 확장이 가능하므로 확장성은 동점이고, 결정은 "이 볼트의 [[구조적 원칙]] 7개와 두 하이라이트를 무엇이 가장 자연스럽게 담는가"로 갈렸다는 것이다. NestJS가 Guard=역할 권한, Interceptor=연락처 노출 통제, event-emitter=도메인 이벤트로 거의 1:1 대응한다. 방향은 스타트업·스케일업으로 정했고 그래서 C(Spring)를 택하지 않았다.

**시안 HTML은 지금 고치지 않는다.** 시안의 역할은 판단을 끝내는 것이고 그 판단은 노트에 남았다. 같은 수정을 시안과 코드 두 번 하지 않고 코드에서 한 번만 한다.

**친구들과의 시안·기획 합의는 보류.** 이대로 진행하고 나중에 공유하기로 했다.

**공종 정본은 [[엔티티 - WorkCategory]]의 시드 13종이다.** 시안에서 화면마다 5갈래로 갈라져 있던 것을 유저 스토리 문서 상단의 「용어와 상수」 절에 정본으로 박았다. 화면이 다른 목록을 들고 있으면 그 화면이 틀린 것이다.

**이미지 용량 상한은 장당 10MB가 정본이다.** 시안에서 의뢰 20MB / 포트폴리오 10MB로 갈라져 있던 것을 PRD에서 하나로 잠갔다. 성능 목표 수치는 볼트에 근거가 없어 `가정:`으로 명시했고, 시드 데이터로 실측한 뒤 갱신하기로 했다. 그 전까지는 목표가 아니라 자리 표시자다.

마지막으로 P1-3 범위 잠그기를 했다. Must 30개를 시간으로 환산하고 잘라낼 것을 `brain/70-산출물/백로그.md`로 옮겼다.

**기간 가정이 틀렸다는 것이 이 세션의 두 번째 큰 발견이다.** Must 30개가 413시간(주 30시간 기준 14주)으로 나왔고 이는 기존 가정 4~6주의 2.3~3.4배다. 범위를 다듬어 맞출 수 있는 차이가 아니라서 **Must를 24개로 줄이고 기간 가정을 8~10주로 수정**했다. 6주를 고수하려면 이미지 파이프라인이나 컨택 상태머신 중 하나를 포기해야 하는데 그건 이 프로젝트를 하는 이유를 포기하는 것이라 하지 않았다. 잘라낸 것은 카카오 로그인, 관리자 화면 2개, 신고 플로우 분리, 시공자 목록(C-06), 알림 목록(G-04), 평수·주거형태 필터, 스크랩, 다크모드다.

## 무엇이 막혔는가

막힌 것은 없다. 다만 검수에서 **[[확장 규약]] 위반 4건**이 나온 게 이 세션의 가장 중요한 발견이다. 평수와 지역이 자유 텍스트 인풋이고, 의뢰 사진의 출처(SELF/EXTERNAL)와 `source_url`이 아예 없고, 공종 목록이 파일마다 5가지로 갈라져 있다. 시안은 그림이 아니라 앞으로 만들 폼의 명세이므로 이대로 구현하면 2차에 스키마를 갈아엎어야 한다.

비용 공개를 불리언으로 끝낼지는 결정하지 못하고 [[열린 질문]] Q6으로 남겼다.

## 볼트를 재구성했다

세션 끝에 산출물의 자리를 바꿨다. PRD·유저 스토리·백로그·ADR을 `docs/`에 두고 있었는데 **그 폴더는 GitHub Pages로 인터넷에 공개된다.** 경쟁 분석과 리스크, 수익 모델 논의가 담긴 문서를 거기 두는 건 `brain/`을 공개에서 제외한 이유와 정면으로 충돌한다.

그래서 `brain/70-산출물/`을 새로 만들어 전부 옮기고, ADR은 원래 있어야 할 `brain/50-결정/`으로 보냈다. 볼트 안은 이미 gitignore 대상이라 별도 조치 없이 비공개가 된다. 참조 경로 40여 곳을 일괄 갱신했고, [[노트 작성 규칙]]에 **"산출물은 파생물이고 원 노트가 이긴다"**는 조항을 추가했다. 이게 없으면 같은 정보가 두 곳에 살면서 한쪽이 조용히 낡는다.

`docs/`에는 이제 목업 HTML만 남는다. 공개해도 되는 것만 있는 상태다.

## 코드가 생겼다 (P2-2)

승인받은 트리대로 pnpm 모노레포를 만들었다. `apps/api`(NestJS) · `apps/web`(Next.js) · `packages/domain`(순수 TS) · `packages/shared`(공용 타입·상수). 기능 코드는 넣지 않았고 뼈대만이다.

가장 중요한 성과는 **[[구조적 원칙]]이 문서가 아니라 강제 장치가 됐다는 것**이다. 도메인에 `@nestjs/common`을 import 하는 파일을 만들어 실제로 확인했다 — 패키지 경계가 막고 ESLint가 "근거: brain/30-설계/구조적 원칙.md 1·2조"를 가리키며 에러를 낸다. 어댑터 포트 넷(storage·notification·event-bus·search), `EstimatePolicy`+`NoopEstimatePolicy` 배선, 커서 페이지네이션 타입, 도메인 에러→HTTP 매핑 필터도 함께 넣었다.

그리고 **시안의 분열을 코드로 봉합했다.** 공종 13종과 이미지 10MB 상한을 `packages/shared`에 정본으로 두었다. 이제 화면이 다른 목록을 들고 있으면 그 화면이 틀린 것이 된다.

**막힌 것 하나.** 이 PC의 Windows Application Control 정책이 서명되지 않은 네이티브 모듈을 차단해서 `@swc/core`가 로드되지 않는다. 원래 vitest+SWC로 러너를 통일하려 했는데 불가능했다. 보안 정책을 끄는 대신 네이티브 바이너리가 필요 없는 **ts-jest**로 갔고, 부수 효과로 빌드와 테스트가 같은 컴파일러를 쓰게 됐다. Next.js와 esbuild는 정상이라 다른 곳엔 영향이 없다. 같은 증상을 다시 만나면 이게 원인이다.

검증은 build · typecheck · lint · test · format 다섯 개가 전부 통과했다. 커밋 `c7294e6`.

이어서 P2-3으로 `CLAUDE.md`를 실제 구조에 맞춰 다시 썼다. 139줄로 상한(200) 안에 들어왔고 색인 성격을 유지했다 — 판단의 근거는 전부 brain 링크로 넘기고 여기에는 "어디를 봐야 하는가"와 "무엇을 하면 안 되는가"만 남겼다.

가장 값이 나갈 부분은 **새 기능을 추가하는 순서**다. shared 상수 → domain 규칙과 테스트 → ports → infra 구현 → api 모듈 → common(권한·직렬화) → web 화면 순으로, **안에서 바깥으로** 짜게 못 박았다. 바깥에서 안으로 짜기 시작하면 규칙이 컨트롤러에 눌러앉고 도메인이 껍데기가 된다.

금지 목록 11개도 넣었다. 도메인에서 프레임워크 import, `any`, 상태 컬럼 직접 UPDATE, 오프셋 페이지네이션, 목록의 원본 이미지, 한글 라벨 DB 저장, 자유 텍스트 평수, ACCEPTED 아닌데 `phone` 노출, `process.env` 산발 접근 같은 것들이다. 대부분은 이미 ESLint나 패키지 경계가 막지만, 막히는 이유를 사람이 읽을 수 있는 자리에 적어뒀다.

## 다음에 무엇을 할 것인가

**Phase 3 — P3-1 ERD.** 엔티티 노트 다섯이 입력값이다. 만들 때 [[시안 검수 결과]]가 지목한 [[확장 규약]] 위반 셋이 스키마에서 실제로 해소됐는지 확인한다. `area_pyeong DECIMAL`에 자유 텍스트 컬럼 없음, `sido_code`/`sigungu_code`에 주소 원문 컬럼 없음, `WorkCategory` 코드 테이블에 한글 라벨 컬럼 없음. 그리고 `source_type`/`source_url`과 `estimate_snapshot JSONB NULL`이 자리를 잡아야 한다.
