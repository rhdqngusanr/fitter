# MVP 범위

> 이번 사이클에 만드는 것과 만들지 않는 것. **범위 밖의 것을 임의로 만들지 않는다.**
> **확정: 2026-07-25 (P1-3).** 상세 근거와 추정치는 `brain/70-산출물/백로그.md`, 확정 범위는 `brain/70-산출물/PRD.md` 6.0절.

## 기간 가정이 바뀌었다 (2026-07-25)

P1-3에서 유저 스토리 `Must` 30개를 보수적으로 환산한 결과 **413시간**이 나왔다. 주 30시간 기준 14주이고, 기존 가정 4~6주의 **2.3~3.4배**다. 범위를 조금 다듬어 맞출 수 있는 차이가 아니다.

그래서 `Must`를 **24개로 줄이고(약 314시간) 기간 가정을 8~10주로 수정한다.** 잘라낸 것은 카카오 로그인, 관리자 화면 2개, 신고 플로우 분리, 시공자 목록(C-06), 알림 목록(G-04), 평수·주거형태 필터, 스크랩, 다크모드다.

**이미지 파이프라인과 컨택 상태머신은 자르지 않았다.** 6주를 고수하려면 둘 중 하나를 포기해야 하는데, 그건 이 프로젝트를 하는 이유를 포기하는 것이다.

## 만드는 것

**인증과 역할**
이메일 회원가입·로그인, 소셜 로그인 1개(카카오 우선), 가입 직후 역할 선택 온보딩, 역할 기반 라우팅과 권한. 자세히는 [[권한 모델]].

**고객 — 레퍼런스 의뢰 등록**
사진 다중 업로드(출처 정보 포함), 공종 다중 선택, 평수, 주거형태, 지역, 희망 시기, 거주 중 여부, 자재 등급 선호, 예산 범위(선택). 필드 상세는 [[엔티티 - ReferenceRequest]].

**시공자 — 포트폴리오 등록**
사진 다중 업로드, 공종, 평수, 지역, 작업 기간, 시공 연월, 실제 비용 공개(선택). 프로필은 상호, 소개, 경력, 보유 공종, 활동 지역. 상세는 [[엔티티 - PortfolioItem]].

**탐색**
의뢰 목록, 시공자 목록, 포트폴리오 갤러리. 공종·지역·평수·주거형태 필터, 커서 페이지네이션, 무한 스크롤, URL 동기화.

**컨택**
양방향 매칭 요청과 상태 관리. 연락처는 수락 이후에만 공개. 상세는 [[상태머신 - 컨택]].

**부가**
스크랩(찜), 신고, 인앱 알림, 관리자(시공자 승인·신고 처리).

## 만들지 않는 것

| 항목 | 왜 지금 안 하는가 |
|---|---|
| 자동 견적·정찰제 가격 | 데이터가 없으면 계산이 불가능. 2차. [[리스크 - 가격 신뢰]] |
| 인앱 채팅 | 연락처 공개로 대체 가능. 구현 비용 대비 MVP 가치 낮음 |
| 리뷰·평점 | 거래 검증 없이는 신뢰도가 없다. 거래 데이터가 먼저 |
| 안전결제·에스크로 | 전자금융업 등록 등 법적 요건. 개인 프로젝트로 불가 |
| 표준 계약서·전자서명 | 2차 |
| 일정·공정 관리 | 범위 폭발 위험 |

**하지만 설계가 이것들을 막으면 안 된다.** 그게 [[확장 규약]]의 존재 이유다.
