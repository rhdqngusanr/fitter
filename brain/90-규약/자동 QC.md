# 자동 QC

> 이 볼트의 규약을 **기계가 검사하게 만든 장치.** 실행은 `pnpm qc`.
> 구현은 `scripts/qc/`.

## 왜 만들었나

Phase 0~2 동안 사람이 손으로 찾아낸 문제들이 있었다. [[시안 검수 결과]]가 그 기록이다.

- 평수와 지역이 자유 텍스트 입력이었다 ([[확장 규약]] 1·3조 위반)
- 공종 목록이 화면마다 **다섯 갈래로 갈라져** 있었다 (2조 위반)
- 이미지 용량이 20MB와 10MB로 나뉘어 있었다
- 금지어 "견적"이 사용자 카피에 노출돼 있었다
- 승인(`is_approved`)을 "인증"이라 부르는 용어 드리프트가 있었다

이것들의 공통점은 **읽어보면 보이지만 안 읽으면 안 보인다**는 것이다. 그리고 시안 8개 4,400줄을 매번 사람이 읽을 수는 없다. 그런 건 기계가 봐야 한다.

그래서 검사 항목은 전부 **실제로 터졌던 것에서 왔다.** 가설로 만든 규칙은 하나도 없다. 이게 이 도구가 노이즈가 되지 않는 이유다.

## 무엇을 검사하나

| 검사 | 대상 | 잡는 것 |
|---|---|---|
| `vault` | `brain/` | 끊어진 위키링크, 고아 노트, 프론트매터 필수 필드와 type, 연결 섹션 |
| `glossary` | 시안·코드 | 금지어(견적·매칭 완료·업체), 용어 드리프트(인증 → 승인) |
| `expansion-rules` | 시안·코드 | 자유 텍스트 평수·지역, 공종 목록 중복 정의, 용량 상수 하드코딩 |
| `structure` | 코드 | 도메인의 프레임워크 import, `process.env` 산발 접근, 오프셋 페이지네이션, 전화번호 리터럴 |
| `design-tokens` | 시안·코드 | 시안 정본과 토큰 이름이 같은가 (`--shadow-1` 을 `--shadow-sm` 으로 고치면 대조 불가) |
| `typography` | 코드 | 크기를 숫자로 적지 않았는가. 2026-07-26 에 101건 → 0 이 되어 error 로 잠갔다 |
| `routes` | 코드 | **없는 화면으로 가는 링크**(error) / **도달할 수 없는 화면**(warn) |

`routes` 는 2026-07-26 에 붙였다. 위의 「앞으로 붙일 것」에 있던 "화면 목록 정합성"이
이것이고, **두 번 겪은 결함**이 근거다 — `프로필 전체 보기` 가 404 였고, C-03 을
만들었는데 목록 카드에 링크가 없어 도달할 수 없었다. 둘 다 타입 검사를 통과한다.

## `pnpm qc` 는 1층이다

**중요한 구분이다.** `pnpm qc` 통과를 "화면을 검사했다"로 읽으면 안 된다 —
이 프로젝트가 실제로 겪은 문제가 그것이었다. 시안과 다른 화면이 전부 통과한 채로 쌓였다.

| 층 | 도구 | 자동인가 |
| --- | --- | --- |
| 1. 정적 | `pnpm qc` | **자동.** 커밋 전 강제 |
| 2. 렌더 | `/qc-screens` (브라우저) | 불러야 돈다 |
| 3. 판단 | `/qc-screens` (같은 실행) | 불러야 돈다 |

무엇을 왜 보는지는 [[화면 QC 목록]]에 있다. **2·3층은 회귀를 막지 못한다** —
매번 부르지 않으면 안 돈다. 관문이 필요하면 단정문이 필요하다 → [[열린 질문]] Q11

## 두 가지 설계 판단

**첫째, `design/`은 warn이고 코드는 error다.** 시안은 고치지 않기로 했고 그 판단은 이미 [[시안 검수 결과]]에 남았다. 그런데 같은 문제를 매번 error로 띄우면 도구 전체가 무시당한다. 대신 코드에서 같은 실수가 나오면 그때는 빌드를 막는다. **아직 안 고친 부채와 새로 생긴 잘못은 구분해야 한다.**

현재 상태는 `0 error · 55 warn`이다. 55건은 전부 시안이고 전부 이미 아는 것들이다.

**둘째, 모든 지적은 근거 노트를 함께 출력한다.** 무엇이 문제인지와 어디인지만 있으면 사람은 "이거 그냥 꺼도 되나?"를 판단할 수 없다. 왜 그게 규칙인지가 붙어 있어야 규칙이 살아남는다.

## 오탐을 줄이려고 한 것

처음 돌렸을 때 오탐이 나왔고, 전부 **주석을 사용자 카피로 오인한** 경우였다.

- `EstimatePolicy`를 설명하는 주석의 "견적" — 이건 [[확장 규약]] 5조가 정한 정식 도메인 이름이다
- "매칭 완료 상태는 만들지 않는다"라고 적어둔 주석 자체
- "`process.env`를 아무 데서나 읽지 않는다"라고 적어둔 주석 자체

그래서 코드에서는 **문자열 리터럴만** 검사하고 주석은 건너뛴다. 테스트 이름도 제외한다 — 금지어 규칙이 막으려는 건 사용자가 화면에서 "견적"을 보고 금액이 확정된다고 오해하는 것이지, 개발자가 도메인 개념을 부르는 방식이 아니다.

**규칙을 설명하는 문장과 규칙을 어기는 코드는 다르다.** 이걸 구분하지 못하면 도구가 자기 문서를 고발한다.

## 앞으로 붙일 것

구현이 쌓이면 검사도 같이 자란다. 지금은 뼈대뿐이라 잡을 게 적은 항목들이다.

- **연락처 노출** — `phone`이 `ACCEPTED`가 아닌 응답 DTO에 실리는지. [[권한 모델]]의 가장 위험한 지점이라 P4-6 이후 반드시 넣는다
- **목록의 원본 이미지** — 목록 응답에 썸네일이 아닌 키가 들어가는지
- **한글 라벨 DB 저장** — 공종·enum이 코드가 아니라 라벨로 저장되는지
- ~~화면 목록 정합성~~ — `routes` 로 붙였다 (2026-07-26)

## 언제 도나

수동(`pnpm qc`)이 기본이고, **2026-07-26 에 Stop 훅을 붙였다.**

`.claude/settings.json` 의 Stop 훅이 `scripts/qc/hooks/stop-web-check.mjs` 를 돌린다.
`apps/web` 의 `.tsx`·`.css` 가 커밋 안 된 상태로 바뀌었을 때만 동작하고,
1층을 실제로 돌린 뒤 **"2·3층은 아직 안 돌았다"고 말한다.**

두 번째가 이 훅의 존재 이유다. 1층 통과가 "화면을 검사했다"로 읽히는 것을 막는다.

**훅은 막지 않는다.** QC error 가 있어도 알리기만 한다 — 훅이 턴을 막으면 고치라고
되돌리는 루프가 생기고, error 가 의도된 것일 때 빠져나갈 방법이 없어진다.

CI 는 아직 없다([[진행 현황판]] P5-3). 붙일 때 **커밋마다 4,400줄을 훑는 비용**이 있으니
pre-commit 에는 변경된 파일만 넘기는 방식이 맞다.
