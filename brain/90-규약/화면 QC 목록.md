# 화면 QC 목록

> **이 목록의 출처는 실제로 겪은 결함이다.** 상상한 항목은 넣지 않았다.
> 2026-07-26 두 번의 대조에서 브라우저로 잡은 20건이 이 목록의 뼈대다.
>
> 실행 절차는 `.claude/skills/qc-screens/SKILL.md` 에 있다. 여기는 **무엇을 왜 보는가**다.

## 세 층으로 나눈다

무엇이 무엇을 잡을 수 있는지가 다르다. 섞으면 "다 봤다"고 착각한다.

| 층 | 도구 | 잡는 것 | 못 잡는 것 |
| --- | --- | --- | --- |
| **1. 정적** | `pnpm qc` | 토큰·타이포·용어·라우트·확장 규약 | 렌더 결과, 상태, 의미 |
| **2. 렌더** | `/qc-screens` (브라우저) | 빈 화면, 숨은 컨트롤, 안 뜨는 상태, 치수 | 문장의 의미 |
| **3. 판단** | `/qc-screens` (같은 실행) | 모순·거짓 약속·읽히는 방식 | 회귀(다시 안 돈다) |

**1층만 자동이다.** 2·3층은 사람이나 에이전트가 불러야 돈다. 그래서
`pnpm qc` 가 통과했다는 말과 "화면을 검사했다"는 말은 **다른 말이다.**

## 1층 — `pnpm qc` (자동, 커밋 전 강제)

| 검사 | 무엇 | 심각도 |
| --- | --- | --- |
| `vault` | brain 링크·고아 노트·프론트매터 | error |
| `glossary` | 금지어(`견적`), 용어 통일(`승인` vs `인증`) | 코드 error · 시안 warn |
| `expansion-rules` | 평수·지역 자유 텍스트, 공종 목록 분열, 용량 하드코딩 | 코드 error · 시안 warn |
| `structure` | 도메인 순수성, `process.env` 직접 읽기, 전화번호 리터럴 | error |
| `design-tokens` | 시안 정본과 토큰 이름이 같은가 | error |
| `typography` | 크기를 숫자로 적지 않았는가 | error |
| `routes` | 없는 화면으로 가는 링크 / 도달할 수 없는 화면 | 링크 error · 도달 warn |

`routes` 는 2026-07-26 에 추가했다. **두 번 겪은 결함**이 근거다 —
`프로필 전체 보기` 가 404 였고, C-03 을 만들었는데 목록 카드에 링크가 없어
도달할 수 없었다.

> [!warning] `routes` 가 못 잡는 것
> **조건부 404 는 못 잡는다.** `/pros/:id` 는 라우트가 있지만 승인·비휴면·활동명
> 셋을 안 맞추면 404 다. 그건 2층이 눌러봐야 안다.

## 2층 — 렌더 검사 (브라우저로 확인)

### R1. 화면이 실제로 그려지는가

**가장 먼저 본다.** 이걸 건너뛰면 나머지가 무의미하다.

- 렌더 후 `#main` 이 비어 있지 않은가
- 콘솔 에러 0
- 스켈레톤이 영구히 남아 있지 않은가

> 근거: `.next` 가 덮여서 **SSR HTML 에는 내용이 있는데 브라우저 DOM 은 빈
> Suspense 경계뿐**인 상태를 겪었다. 콘솔 에러도 서버 에러도 없었다.
> → [[진행 현황판]] 경고

### R2. 숨어서 못 고르는 컨트롤이 없는가

- `scrollWidth > clientWidth` 인 컨테이너에 **선택해야 하는** 항목이 들어 있지 않은가
- 스크롤바를 숨긴 곳(`scrollbar-width:none`)에 "더 있다"는 신호가 있는가

> 근거: 공종 13종이 578px 칸에 1056px 로 깔려 6개가 숨은 스크롤 뒤에 있었다.
> 훑는 목록이면 손실이 적지만 **자기 공종을 고르는 폼에서는 못 고르는 것과 같다.**
> → [[시안 검수 결과]] 7번

### R3. 모바일에서 가로 스크롤이 없는가

- 390px 에서 `body.scrollWidth <= window.innerWidth`
- 넓은 표는 **자기 컨테이너 안에서만** 스크롤하는가

### R4. 상태가 실제로 갈라지는가

**시안이 그려둔 상태 수가 완료 기준이다.** 각 상태를 실제로 만들어 확인한다.

- 빈 상태 / 로딩 / 에러 / 권한별 분기
- **"아직 못 불러온 것"과 "0건"이 구분되는가**
- 검증 오류가 서버 400 을 받아 실제로 뜨는가 — 필드까지 지목하는가

> 근거: 로드 실패가 머리글만 남은 표로 보여 운영자가 "0건"으로 읽었다.
> 그리고 검증 오류 상태가 **영원히 안 떴다** — 서버는 `details.issues[].path` 로
> 주는데 화면은 `details.field` 를 읽었다.

### R5. 링크가 실제로 열리는가 (조건부 404)

- 승인·소유·상태 조건이 걸린 링크를 **눌러본다**
- 조건을 만족하지 않는 대상에는 링크가 아예 없어야 한다

> 근거: 승인만 확인하고 `공개 프로필 보기` 를 걸었는데 `/pros/:id` 의 조건은
> 승인 + 비휴면 + **활동명 있음** 셋이었다. 활동명 없이 승인된 계정이 실제로 있다.

### R6. 되돌릴 수 없는 조작이 확인을 받는가

- 마감·반려·비공개에 확인 단계가 있는가
- 되돌릴 수 있으면 그 경로가 화면에 있는가
- 되돌릴 수 없으면 **그렇다고 적혀 있는가**

### R7. 치수가 시안과 같은가

시안의 리터럴 값과 `getComputedStyle` 을 대조한다. 전부는 아니고 **골격만**:

- 2단 구성 `grid-template-columns` · `gap`
- 카드 `padding` · `border-radius`
- 터치 타깃 높이(**44px 미만이 없는가** — [[디자인 원칙]])
- 헤더 높이, 앵커의 `scroll-margin-top`

## 3층 — 판단 검사 (에이전트나 사람만 가능)

**이번 결함의 절반이 여기였다.** 단정문으로는 영원히 안 잡힌다.

### J1. 화면의 두 문장이 서로 모순되지 않는가

같은 화면 안에서 두 곳이 다른 말을 하는지 본다.

> 겪은 것: 제안 3건이 깔린 화면에서 우측 패널이 **"제안을 기다리는 중"**이라고 했다.
> 0건과 "아직 수락하지 않음"을 같은 문장으로 묶은 탓이다.

### J2. 버튼이 약속한 곳으로 가는가

라벨이 말한 것과 실제 이동·다음 화면이 같은지 본다.

> 겪은 것: `저장하고 의뢰 보러 가기` 를 눌렀는데 토스트가 `포트폴리오 올리러 가기` 를
> 내밀었다. 저장 후 상태가 갈려서 그때 값으로 토스트를 그린 탓이다.

### J3. 조작 결과 문구가 새 조치로 읽히지 않는가

> 겪은 것: `되돌리기` 를 눌렀는데 토스트가 **"1명 반려했습니다"**라고 했다.
> 내부적으로는 반려가 맞지만 운영자는 그걸 새 조치로 읽는다.

### J4. 카피가 지킬 수 있는 말만 하는가

**화면의 문장을 코드·스키마와 대조한다.** 이게 3층의 핵심이고 가장 많이 걸린다.

- 약속한 기한·정책이 어디서 강제되는가
- 언급한 정렬·가중치가 실제 쿼리와 같은가
- 언급한 제약이 실제 인덱스·검증과 같은가

> 겪은 것 넷: "영업일 1~2일 내 확인"(서류 업로드도 기한도 없다),
> "응답 속도와 수락률이 노출에 반영"(정렬은 등록순이다),
> "공종별로 나눠 올리라"(한 의뢰에 여러 개 담을 수 있다),
> 그리고 **제가 고쳐 쓴 문장도 틀렸다** — "한 의뢰에 두 번 제안 불가"인데
> 인덱스는 `(requester, receiver) WHERE REQUESTED` 로 **상대 단위**였다.
>
> **카피에 규칙을 적을 땐 그 규칙의 정의를 열어봐야 한다.** 기억으로 쓰면
> 그럴듯한 거짓말이 된다.

### J5. 없는 것을 있다고 말하지 않는가

- 세는 곳이 없는 숫자를 보여주지 않는가
- 저장할 곳이 없는 입력을 받지 않는가
- **없는 안전장치를 있다고 하지 않는가**

> 겪은 것: 관리자 사이드바가 "모든 조치는 감사 로그에 남습니다"라고 했다.
> 감사 로그가 없다. 운영자가 그걸 믿고 행동한다.

### J6. 화면 없는 메뉴를 세워두지 않았는가

링크를 걸면 404 고, 회색으로 두면 "곧 나온다"는 약속이 된다. **둘 다 하지 않는다.**

### J7. 화면이 서버보다 무른 말을 하지 않는가

화면이 "할 수 있다"고 하는데 서버가 막는 경우를 찾는다.

> 겪은 것: 미승인 시공자에게 공개 버튼을 그대로 두고 "승인 전에는 갤러리에 안 뜬다"고
> 했다. 서버는 **공개 자체를 403 으로 막는다.** 누를 때마다 실패하는 버튼이었다.

## 무엇을 QC 라고 부르지 않는가

- **`pnpm test` 는 화면 검사가 아니다.** 도메인 순수 함수 + API e2e(supertest)다.
  브라우저를 열지 않고, 웹 테스트 파일은 0개다
- **`pnpm qc` 통과 = 1층 통과**다. 2·3층은 따로 돌려야 한다
- **3층은 회귀를 막지 못한다.** 매번 다시 부르지 않으면 안 돈다.
  관문이 필요하면 단정문(Playwright)을 더해야 한다 → [[열린 질문]] Q11
